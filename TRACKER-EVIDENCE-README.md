# Конкуренты / Trend Alerts — проверяемый Outlier v0.12.30

Это продолжение пункта 4 плана, не полная копия vidIQ и не сигнал успеха/спроса. Откройте **Конкуренты → Видео**: под таблицей есть база каждого ролика. Таблица прокручивается внутри карточки; раскрываемые исходники доступны также на мобильном экране.

## Формула и исходники

Outlier = известные просмотры цели / медиана просмотров **минимум 3 других уникальных видео** этого же канала. Сам ролик исключается. Группы: ≤180 с и >180 с по известной длительности; это не подтверждённый статус Shorts. Неизвестная длительность/канал источника/счётчик цели блокируют коэффициент.

Каждый ролик базы должен иметь подтверждённый источник канала, известную длительность и известный неотрицательный целый счётчик, последний снимок не старше 48 ч и не из будущего, корректную публикацию, возраст ≥48 ч **на дату своего наблюдения** и ту же группу длительности. Нулевые просмотры участвуют, неизвестные — нет. Повторы ID исключаются. Нужны минимум 3 других ролика и положительная медиана; нет перехода к среднему или другой группе.

Раскрытие показывает время расчёта UTC, просмотры цели, медиану, число вошедших строк и каждую сохранённую строку: ID/заголовок, публикацию, длительность, дату счётчика, просмотры и причину включения/исключения. Метаданные/счётчики читаются последовательно, не одновременно. База — ограниченные сохранённые загрузки, не весь канал и не нормализация возраста видео. В последние ≤48 ч могли входить наблюдения предыдущего обновления. Коэффициент в интерфейсе округлён до двух знаков, порог сравнивается с неокруглённым отношением.

Общая «медиана длинных» убрана: для разных целей знаменатель разный. Поле совместимости API medianViews теперь null с пояснением; новый коэффициент и база — videos[].outlier / outlierBasis. Вспомогательный прежний compBase оставлен только для совместимости старого кода и тестов, не для нового трекера/дайджеста.

## Алерт — отдельное сохранённое основание

Новый Outlier-алерт содержит outlierEvidence версии 1: всю базу, отношение, время расчёта и порог. Последующее обновление, смена настроек, GET и экспорт не пересчитывают его. Первый сбор канала и ролики старше 30 дней не создают новый Outlier-алерт. Сигнал формируется только для ролика, получившего новое наблюдение в этом обновлении, при положительном пороге и его достижении. Тег outlier-v1 не даёт повторять сигнал для этого ролика; удаление/повторное добавление канала начинает новую историю. Старый тег outlier не считается доказательством новой методики.

Старые алерты остаются с прежним текстом и предупреждением: исходная база неизвестна. GET не дописывает им происхождение данных. Старые видео без явно сохранённой длительности/канала источника не получают новый Outlier только от открытия страницы — сначала нужен новый сбор. Интервальные всплески VPH и публичные счётчики подписчиков сохраняют свои прежние отдельные правила (TREND-ALERTS-README.md / CHANNEL-COUNTERS-README.md); явно неизвестная длительность теперь блокирует новый всплеск. Старые интервальные точки не мигрируются.

## Обновление, стоимость и сбои

Одна свежая страница последних 5–50 загрузок на канал по настройке, без кеша/пагинации. До **1 + 2×N** базовых единиц за N≤50 каналов: channels.list + playlistItems.list и videos.list на канал. При пустой странице videos не вызывается. Добавление отдельно разрешает ссылку/handle/ID. Повторы, резервные ключи, общая диагностика ключей и другие работающие разделы — отдельно; это оценка, не измеритель реального расхода.

Чтение трекера/алертов, раскрытия и ZIP не обновляют YouTube. Расписание работает только при работающем сервере, проверяется раз в 15 минут; интервалы/пороги в Настройках. Обновление данных не вызывает AI, но отдельно включённый авто-дайджест может его вызвать. Нет Windows/почтовых push-уведомлений.

Чужие каналы в метаданных, повторы ID и ошибки/404 страницы не становятся успешной пустой выборкой. Видео/их точки при ошибке загрузок сохраняются, выводится безопасное сообщение. Снимок публичных счётчиков канала может при этом обновиться — это отдельный результат. Ответ обновления содержит число обработанных каналов и неполных обновлений; refreshed — совместимое число обработанных, не обещание полного успеха. При общем сбое channels.list обновление завершается ошибкой до записи. Доступные видео из частично отсутствующего ответа videos сохраняются, отсутствующие не получают новую точку/алерт. Более старое параллельное наблюдение не дописывается после нового.

Повреждённый, слишком большой (>32 МиБ), недоступный файл или symlink competitors.json дают явную ошибку вместо пустого трекера. Из такого файла не начинается обновление/добавление; он не перезаписывается. Чтение ограничено, запись атомарная через приватный временный файл (0600 на Linux). Только отсутствие файла означает новый пустой трекер. Не чините повреждение удалением файла: восстановите защищённую резервную копию. Входные refresh-запросы ограничены 8 КиБ; неверный JSON, пустые/повторные/некорректные IDs не означают «обновить всех».

## Дайджест и перенос

Новые дайджесты используют тот же per-target Outlier и сохраняют базу вместе с выбранными видео; основание раскрывается на экране. AI получает компактное n/median/reason, а не всю матрицу базы. Его выводы — гипотезы по ограниченному контексту, не причины успеха, измеренный спрос или насыщенность. Старые дайджесты не пересчитываются. Полный точный предпросмотр AI-запроса дайджеста в этом этапе не реализован.

competitors.json и digests.json уже входят в общий ZIP данных; перенос сохраняет новые основания. ZIP приватен и может содержать OAuth/личные материалы других разделов. Исходный ZIP релиза не включает .env, DATA_DIR, токены, логи, node_modules или сборки. Перед обновлением остановите сервер, сохраните копию .env/DATA_DIR/промптов; распакуйте исходники в прежнюю папку и запустите update-windows.bat. Архив — исходники, не установщик.

Реальные Google/AI, квота и обновление/ярлык Windows здесь не проверялись. Проверки синтетические; весь план, CTR Reporting и автоматические A/B остаются открытыми.
