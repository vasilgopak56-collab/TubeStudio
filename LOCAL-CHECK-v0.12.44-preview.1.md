# Обновление и проверка v0.12.44-preview.1

## Безопасное обновление Windows

1. Завершите задания TubeStudio и сохраните правки. Сделайте резервную копию: при остановленном сервере отдельно сохраните DATA_DIR, папку промптов и .env вне установки. ZIP-экспорт не включает .env и может содержать OAuth и личные данные — не публикуйте его.
2. Закройте старый сервер через Ctrl+C в окне запуска либо stop-windows.bat этой установки. Помощник требует windows/server-control.mjs рядом в подкаталоге и подтверждение. Он принудительно завершает только однозначно распознанный собранный сервер; не применяйте его во время задач. Закрытая вкладка не останавливает сервер.
3. Если старый запуск через относительный npm start/dist/index.js не распознан, используйте Ctrl+C в исходном терминале. Не завершайте все node.exe. При невозможности найти старое окно сохраните работу других программ и выполните обычную перезагрузку Windows; не запускайте старую копию до обновления.
4. Обновите файлы программы из архива, сохранив свои .env, data и пользовательские промпты. Не заменяйте изменённые промпты стандартными вслепую. Если у вас есть свои правки кода — сначала сохраните их и объедините изменения в редакторе. Архив — исходный проект, не готовый установщик и не резервная копия ваших данных.
5. Запустите update-windows.bat из папки с package.json. Дождитесь завершения установки зависимостей и сборки. При ошибке остановитесь, не запускайте смешанные старые/новые файлы. update-windows.bat не сохраняет вашу резервную копию за вас.
6. Запустите приложение новым start-windows.bat или ярлыком. Обновите браузер Ctrl+F5; должна показываться v0.12.44-preview.1. При разных версиях интерфейса/сервера перезапустите именно обновлённую установку. diagnose-windows.bat помогает проверить файлы, но не заменяет проверку приложения.

Нативный Windows-запуск этой сборки в среде разработчика не выполнялся. stop-windows.bat не предназначен для Vite/tsx в режиме npm run dev; их останавливают Ctrl+C в терминале разработки.

## Что проверить в приложении

1. Откройте старый проект/расчёт без генерации: сохранённая история должна оставаться доступной. Не проверяйте восстановление ZIP поверх единственной рабочей копии; отдельная процедура есть в LOCAL-CHECK-v0.12.43-preview.1.md.
2. Откройте «Моя аналитика → Показы и CTR», выберите нужное подключение. Нажмите «Обновить задания Google» — это явный запрос, расходует квоту Google. Если список читается, ошибки специально провоцировать не нужно: **не отключайте рабочий API и не удаляйте OAuth ради проверки подсказок**.
3. Если отказ действительно возникает, сообщение должно назвать Data API (проверка канала) или Reporting API и, только если Google прислал известный код, указать причину. При неизвестной причине так и будет написано. Не присылайте Client secret, oauth.json, токены, полные ссылки скачивания или архив данных.
4. Существующее Reach Basic-задание повторно создавать не нужно. Нажмите «Показать готовые отчёты» у него. Если файлов нет, это не нули статистики. Подготовка выполняется Google; не удаляйте и не создавайте задание заново для ускорения.
5. Когда появится отчёт, вручную выберите его, введите название снимка и нажмите «Загрузить и сохранить CSV». Сервер читает CSV и сохраняет нормализованный снимок; исходный CSV не скачивается этой кнопкой в папку браузера. Запишите результат и проверьте историю после перезапуска.
6. Для сверки используйте «Reach JSON» и YouTube Studio: одно и то же видео, дата и доступные показы/CTR. Пока числовая шкала не подтверждена на реальном примере, TubeStudio сохраняет raw ctrApi, не приписывает ему знак процента и не пересчитывает произвольно. Протокол: REACH-CTR-VERIFICATION.md и POINT-12-STEP-BY-STEP.md. Для отчёта достаточно 1–3 обезличенных значений, не всего файла с личными данными.
7. После неоднозначной ошибки команды создания/удаления сначала перечитайте список заданий; не нажимайте повтор вслепую. В .44 автоматических повторов этих команд нет.

## Повторить автоматические проверки

```bash
npm ci
npm run typecheck
npm run test:unit
npm run build
npm run check:windows
node --test --test-concurrency=1 tests/e2e/reach.test.mjs
npm run test:backup-transfer
```

Для E2E нужен Chromium, путь задаётся CHROME_PATH. Подставные Google-ответы из tests/e2e/fixtures/reach-provider.mjs используются только тестами; обычный запуск не подключает этот файл. TEST_ARTIFACTS_DIR задаёт каталог PNG нового сценария.

Полная регрессия без расширения (Bash):
```bash
files=()
for f in tests/e2e/*.test.mjs; do
  [[ "$f" == */extension.test.mjs ]] || files+=("$f")
done
node --test --test-concurrency=1 "${files[@]}"
```

npm run test:e2e включает расширение и не равен этому прогону. Реальный smoke с ключами не запускался; он может расходовать квоту/деньги. Локальные подставные ответы не принимают живую интеграцию Google и платный AI.
