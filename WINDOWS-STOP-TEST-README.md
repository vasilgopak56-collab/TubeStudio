# Изолированная проверка остановки Windows — комплект 2.1.0

Тест предназначен для помощника v0.12.147. Нативная проверка этой версии ещё не выполнялась: разработка и переносимые тесты проведены на Linux.

1. Распакуйте полный комплект в отдельную доступную для записи папку. Не запускайте из ZIP. Нужны Node.js 22 или 24 и доступный Windows PowerShell; интернет, ключи и npm-зависимости для теста не нужны.
2. Запустите `test-stop-windows.bat` обычным пользователем, подтвердите Y. Тест создаёт искусственные серверы на локальных портах во временных папках; рабочую TubeStudio специально закрывать не требуется.
3. Проверьте свежий `windows-stop-test-report.json`: `testKitVersion: "2.1.0"`, `helperVersion: "2.1.0"`, `prepareMethod: "node-server-control-cli"`, `nativeExecution: true`, `status: "passed"`, `cleanup: "passed"`. Старый отчёт не является результатом нового запуска. В успешном отчёте 11 шагов.
4. Можно прислать только отчёт, предварительно просмотрев его. Тест пишет фиксированные поля без ключей, командных строк, путей, имён аккаунтов, PID и данных проектов. Не присылайте `.env`, ключи или личные проекты.

Проверяются dry-run, мягкая остановка своего синтетического сервера, чужая установка, старый относительный путь, другой порт и несколько процессов. Настоящий `update-windows.bat`, npm, приложение, AI и Google не запускаются. Для проверки помощник локально читает командные строки процессов Node.js, включая сторонние, но не записывает и не выводит их. Если данные недоступны или другой процесс похож на относительный запуск TubeStudio, тест может отказать; это не доказывает, что чужая программа является TubeStudio.

Тест убирает только собственные тестовые процессы и временные файлы. Если очистка не подтверждена, сообщите об этом; не завершайте все процессы Node.js. Не отключайте защиту системы и не запускайте от администратора вслепую. Успех не подтверждает работу полного приложения, ярлыка, реального обновления, Windows ACL, восстановления данных или всех конфигураций.
