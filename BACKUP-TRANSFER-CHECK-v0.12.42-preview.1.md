# Проверка переноса v0.12.42-preview.1

Статус: **локальная проверка Linux пройдена; нативная Windows-приёмка открыта**. Код приложения и формат ZIP не менялись. Добавлены повторяемый тест и документация; номер версии остался прежним. Расширение не менялось.

## Выполнено
Два отдельных аутентифицированных процесса сервера, разные DATA_DIR, PROMPTS_DIR и синтетические .env, пути с пробелами/Unicode. Весь серверный fetch провайдеров заблокирован: ни одной попытки обращения. Данные только искусственные, без пользовательских ключей и токенов.

**7 сценариев, 0 ошибок; 42 импортируемых файла, 28 разрешённых каталогов.**

1. Созданы проект с двумя сценариями, бинарный медиафайл, расчёты прибыли v2/ручной/v1, план рекламных пауз с веткой, диалог Coach с закреплённым контекстом, текущий и исходный промпт.
2. Экспорт проверен побайтово: двоичные данные/Unicode, все разрешённые каталоги. .env, кеш, временные файлы, неизвестный каталог и сохранённые oauth-connections исключены. Активный синтетический oauth.json включён — реальный ZIP остаётся конфиденциальным.
3. Импорт в другую установку: все 42 файла совпали; отдельный целевой .env и файлы, которых нет в ZIP, сохранились. Совпадающие файлы заменяются: это объединение, не очистка.
4. Второй сервер полностью остановлен и запущен заново. Проект, расчёты/хеши, архив v1, ветка рекламного плана, Coach, настройки, текущий/исходный промпт прочитаны через API.
5. Изменение текущих цен, журнала расходов и удаление исходной аудиораскадровки не изменили сохранённые снимки. Повторный импорт не добавил дубли ID, байты совпали снова.
6. Повреждённый ZIP, отсутствие manifest, дубли имён без учёта регистра и конфликт файл/каталог отклонены до записи: целевые данные и промпты не изменились.
7. Экспорт/импорт без сессии и с ограниченным токеном расширения отклонены. Внешних API-вызовов не было.

28 каталогов проверены на включение контрольного файла. Это не утверждение о семантической проверке каждой сущности всех 28 разделов. Диалог Coach создан без AI-сообщений; действительность OAuth/доступ к провайдерам этим не проверены.

## Повторить на синтетических данных
Из корня исходников после npm ci:
```bash
npm run test:backup-transfer
```
Команда собирает только сервер, запускает два loopback-процесса на свободных портах, удаляет временные тестовые данные после прогона. Не читает рабочий .env, не импортирует в вашу рабочую установку. Путь к JSON-отчёту выводится в конце; BACKUP_TEST_ARTIFACTS_DIR позволяет указать папку отчёта. Порты выбираются перед запуском, поэтому при редкой коллизии повторите после освобождения порта. Нужен Node.js 20+ и зависимости проекта.

Машинный результат выполненного Linux-прогона: docs/checks/backup-transfer-v0.12.42-preview.1.json. Эти 7 сценариев отдельны от прежних 594 unit / 286 E2E: общая регрессия на этом этапе заново не запускалась.

## Не проверено
- Нативные Windows ACL, junctions, реальные пути/диалоги и обновление .42 на пользовательской установке.
- Большие ZIP, нехватка памяти/места и отказ записи посередине. Импорт не транзакционный; после ошибки ввода-вывода возможны частично записанные файлы.
- Реальный OAuth/Google/Reporting/единица CTR, платный AI, установленный внешний MCP-клиент.
- Новый браузерный сценарий восстановления: здесь проверялся HTTP API, не интерфейс.
