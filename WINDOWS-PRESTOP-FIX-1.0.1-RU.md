# TubeStudio .45 — исправление предварительной остановки Windows

Это точечное изменение Windows-инструментов на базе присланной `0.12.45-preview.1`. Код интерфейса, сервера, MCP, провайдеров и хранения данных НЕ изменён. Версия приложения остаётся `.45`, новый тестовый комплект — `1.0.1`.

## Что исправлено

Раньше тест вызывал `prepare-update.ps1` через PowerShell `-File` без параметра, который использовал обновлятор. При политике `Restricted` этот шаг мог блокироваться. Теперь `update-windows.bat` и тест вызывают существующий `windows/server-control.mjs` напрямую через Node.js. Батник сначала проверяет Node и наличие помощника, затем прерывается при отказе остановки, до npm/сборки.

Логика проверки принадлежности, контроль PID/времени старта/командной строки и отказ для чужой установки НЕ изменены. Остановка принудительная, не штатное завершение задач. Не используйте её во время сохранения или генерации.

Это не полное удаление PowerShell из TubeStudio: помощник использует PowerShell/CIM через команды, а ярлык и его установка остаются на прежнем механизме. Политики Windows не изменяются. Защиту не отключать. Прежний `windows/prepare-update.ps1` оставлен для совместимости, но обновлённый батник и новый тест его не используют.

## Сначала — изолированный тест

1. Распакуйте весь `TubeStudio-Windows-Stop-Test-1.0.1.zip` в новую отдельную папку. Не запускайте из архива.
2. Запустите `test-stop-windows.bat`, нажмите Y. Нужен Node.js 22/24 и доступный Windows PowerShell/CIM. npm и ключи не нужны. Рабочую TubeStudio специально закрывать не требуется.
3. Не меняйте ExecutionPolicy/UAC/антивирус и не повторяйте запуск от администратора ради PASS. Если окно уже повышенное, сообщите это вместе с результатом: само по себе это ещё не диагноз сбоя.
4. Пришлите свежий `windows-stop-test-report.json`. Проверяем: testKitVersion=1.0.1, prepareMethod=node-server-control-cli, nativeExecution=true, status=passed, cleanup=passed и 8 успешных шагов.
5. При FAIL остановитесь и пришлите отчёт, не завершайте все node.exe. Успешный тест подтверждает только искусственные процессы, не всё приложение/обновление.

## Затем — обновление исходников рабочей установки

1. Сохраните изменения и дождитесь завершения задач. Остановите текущий сервер безопасным способом. Если старый относительный запуск не распознаётся, используйте Ctrl+C в его исходном терминале; не убивайте все node.exe.
2. При остановленном сервере сохраните защищённые копии фактического DATA_DIR, `.env`, пользовательских промптов и своих изменений кода. Не публикуйте их.
3. Полный архив содержит папку `tubestudio`. Не запускайте отдельную свежую копию, ожидая увидеть в ней старые проекты: личных данных в архиве нет.
4. Для этого точечного исправления достаточно заменить `update-windows.bat`, `test-stop-windows.bat`, `windows/test-stop.mjs` из полной новой копии. `windows/server-control.mjs` уже совпадает с исходной .45. Тесты и документацию можно обновить вместе с этими файлами. Не переносите старые node_modules/dist поверх нового кода.
5. После завершения тестовой проверки можно проверить обычный запуск, остановку, затем `update-windows.bat`. Этот батник устанавливает npm-зависимости, собирает приложение и пытается обновить ярлык; изолированный тест этих действий не выполняет.
6. После запуска обновите страницу Ctrl+F5. На экране по-прежнему `.45`: комплект не меняет номер приложения. Для идентификации исправления используйте комплект 1.0.1/отчёт/хеши, а не только номер в шапке.

## Папка старого проекта: проверено по коду, не изменено

`apps/server/src/config.ts` вычисляет dataDir относительно рабочего каталога процесса. Windows-запуск и npm workspace запускают сервер из `tubestudio/apps/server`.

| Настройка | Путь при этом запуске |
| --- | --- |
| DATA_DIR отсутствует/пуст | `tubestudio/data` |
| DATA_DIR=./data (есть в .env.example) | `tubestudio/apps/server/data` |
| DATA_DIR — абсолютный путь | Этот абсолютный путь |

Именно поэтому две папки с именем data нельзя считать взаимозаменяемыми. Сначала найдите старые `projects/*.json` и связанные `files/`, затем определите путь, который использует новая установка. Это исправление не переносит проекты, не переписывает DATA_DIR и не объединяет данные автоматически. Путь при произвольном ручном запуске из другого cwd может отличаться. Не присылайте весь .env; при необходимости достаточно сообщить только значение DATA_DIR без прочих строк.
