# Пункт 12: пошаговая проверка своих каналов и CTR

## Зачем мы это делаем
Пункт 12 шире одной цифры CTR: нужно проверить OAuth-доступ к своему каналу, получение данных из Google, сохранение истории и корректность отображения. Начнём с безопасного минимума: один ваш канал, один суточный Reach Basic, одно видео с ненулевыми показами.

В TubeStudio CTR пока показан как исходное число API, без знака %. Нужно сверить, чему это число соответствует в исходной аналитике. Нельзя заранее считать, что число надо умножить на 100, или подставлять CTR всего видео в варианты обложек A/B. Реальную единицу и весь пункт 12 сейчас не считаем принятыми.

## Этап 0. Подготовить программу — несколько минут
1. Сохраните резервную копию. Завершите задачи и остановите старый сервер через stop-windows.bat или Ctrl+C в старом окне. Если процесс не распознаётся, см. WINDOWS-STOP-README.md.
2. Сначала добейтесь успешного обновления, затем запустите TubeStudio. Номер у названия должен соответствовать установленной сборке, сейчас v0.12.43-preview.1. Если интерфейс и сервер показывают разные версии, CTR пока не проверяйте: завершите обновление/перезапуск и Ctrl+F5.
3. Работайте со своим каналом или каналом, к которому у вас законный доступ. Для первой проверки лучше обычное видео с показами, не новый ролик без данных и не только Shorts.

Зачем: сначала исключаем проблему старой сборки/подключения, чтобы не искать её в метриках.

## Этап 1. Подключить свой канал — если ещё не подключён
Если в разделе «Моя аналитика» уже показан правильный подключённый канал, настройку OAuth не повторяйте: перейдите к этапу 2.

Если канала нет:
1. Откройте «Моя аналитика». Разверните встроенную инструкцию OAuth-клиента Google.
2. В Google Cloud Console выберите тот проект, которому принадлежит используемый OAuth-клиент. В APIs & Services → Library включите YouTube Data API v3, YouTube Analytics API и YouTube Reporting API. Публичный YOUTUBE_API_KEY не заменяет OAuth-доступ к приватной статистике.
3. Если OAuth-клиент ещё не создан, следуйте встроенной инструкции TubeStudio. В Google Auth Platform настройте данные приложения; если приложение в Testing, добавьте свой аккаунт в Test users. Не публикуйте приложение и не отключайте требования безопасности только ради этой проверки.
4. По встроенной инструкции создайте OAuth Client ID типа Desktop app («Приложение для ПК»). Client ID/Client secret внесите только локально в поля «Моя аналитика», затем сохраните. Если вы уже используете клиент Web application, не создавайте второй без необходимости: для Web в Google должен быть ТОЧНЫЙ Redirect URI, который TubeStudio показывает под инструкцией. Не подставляйте чужой адрес или другой порт.
5. Нажмите «Подключить YouTube». Войдите своим аккаунтом, выберите нужный канал/бренд-канал, разрешите обычное чтение аналитики. Для показов/CTR финансовый доступ и платный AI не нужны.
6. После возврата сверьте название и ID канала с каналом, который хотите проверить. При неправильном канале остановитесь; не делайте выводы по чужой статистике.

Зачем: Reporting работает с приватными данными именно подключённого канала.

Если возникли redirect_uri_mismatch, access_denied, 403 или запрос заблокирован: не повторяйте вход бесконечно. Пришлите код/текст ошибки без секретов и напишите, на каком шаге она появилась. Ошибка 403 может иметь разные причины; одного кода недостаточно для диагноза.

## Этап 2. Заказать Reach Basic — один раз
1. В «Моя аналитика» откройте вкладку «Показы и CTR».
2. Нажмите «Обновить задания Google». Это чтение уже существующих заданий.
3. Если показано задание channel_reach_basic_a1, не создавайте ещё одно. У нужного задания нажмите «Показать готовые отчёты».
4. Если задания нет, нажмите «Подготовить отчёты в Google» и прочитайте подтверждение. Подтвердите один раз. Эта команда включает ежедневную подготовку файлов на стороне Google, даже если TubeStudio закрыта; видео и обложки не меняются.
5. Если после команды неизвестно, создалось ли задание, сначала снова нажмите «Обновить задания Google», а не создавайте его повторно.

Зачем: Reporting API не отдаёт такой файл мгновенно по произвольной дате; сначала нужно серверное задание подготовки.

## Этап 3. Дождаться файла — возможно до 48 часов
Первый отчёт может появиться в течение 48 часов после создания задания.[^https://developers.google.com/youtube/reporting/v1/reports] TubeStudio и компьютер не нужно держать включёнными для подготовки файлов Google. Автоматического скачивания в программе нет: позже снова откройте вкладку, обновите задания и нажмите «Показать готовые отчёты». При необходимости используйте следующую страницу.

Пустой список сразу после создания — не доказательство ошибки. Возможность исторических файлов зависит от подготовки и доступности Google; не обещайте себе наличие любой даты немедленно.

Не удаляйте задание во время ожидания: удаление прекращает подготовку новых отчётов. Удаление — отдельная операция в Google, не остановка локальной программы.

## Этап 4. Сохранить один суточный отчёт
1. Выберите один уже готовый файл. Лучше день с известной активностью несколько дней назад, а не сегодняшний незавершённый день. Даты списка Google показаны в UTC; дата строк самого отчёта относится к Pacific time/America/Los_Angeles, а не автоматически к вашему часовому поясу.
2. Введите понятное название, например «Проверка CTR — дата отчёта».
3. Нажмите «Загрузить и сохранить CSV» один раз. Появится локальный снимок и строки видео.
4. Запишите дату CSV, ID отчёта и время его подготовки. В таблице выберите одно видео с ненулевыми показами. Зафиксируйте его показы и число «CTR API» точно, не добавляя знак процента и не округляя дополнительно.
5. Нажмите «Reach JSON», если хотите сохранить результат локально. Это приватный снимок: не присылайте весь файл автоматически.

Важно: «Загрузить и сохранить CSV» в текущей программе означает, что сервер скачивает и проверяет CSV Google, а затем сохраняет разобранный снимок. Исходный CSV отдельным файлом в браузер не скачивается и в истории не хранится. Кнопка «Reach JSON» скачивает снимок с исходным числовым ctrApi. Для ПЕРВОЙ сверки этого числа достаточно — не нужно добывать оригинальный CSV через Developer Tools, копировать токены или URL загрузки. Это уточнение прежней просьбы об исходном CSV: он полезен при споре о формате, но не обязателен для первого ручного шага.

Если данных нет/CTR неизвестен/показы нулевые, не заменяйте неизвестность нулём. Возьмите другой готовый день/видео; если подходящих данных нет, результат проверки — «недостаточно данных».

## Этап 5. Сверить одно видео в YouTube Studio
1. Откройте studio.youtube.com под тем же каналом. Для общих отчётов Google указывает путь «Аналитика → Контент».[^https://support.google.com/youtube/answer/9314486?hl=ru]
2. Для точной сверки выберите то самое видео: «Контент → нужное видео → Аналитика», затем раздел охвата/показов (название вкладки может отличаться).
3. Выберите пользовательский период ровно на дату CSV — один день. Не используйте «Последние 28 дней», всю жизнь ролика или весь канал. Если интерфейс не позволяет подтвердить тот же день/часовой пояс, отметьте это как ограничение; не объявляйте расхождение ошибкой программы.
4. Запишите «Показы» и «CTR показов значков» со знаком % и с той точностью, которую показывает Studio. Если краткая карточка округляет, откройте расширенный режим/таблицу для более точного значения, если он доступен.
5. Проверьте сначала охват и показы: тот же ролик, канал, дата. Если показы сильно различаются, сначала нужно выяснить период/задержку/обновление данных, а не подбирать множитель для CTR.

Зачем: мы сравниваем исходное число API и контрольный процент для одной и той же выборки. Просмотры не равны кликам по показам значка; не вычисляйте CTR как все просмотры / показы. Из округлённого CTR нельзя восстанавливать точные клики.

## Этап 6. Что безопасно прислать в чат
Можно переписать вручную (достаточно одного видео; 2–3 строки лучше для проверки):

Версия TubeStudio: ...
Подключён тот же канал: да/нет
Тип: channel_reach_basic_a1
Дата CSV: ...
Интервал Google startTime/endTime (если виден): ...
Видео: A (реальный ID и название не нужны)
Показы TubeStudio: ...
CTR API как показан / ctrApi из Reach JSON: ...
Показы Studio: ...
CTR Studio со знаком %: ...
Период Studio: ровно ... — ...
Часовой пояс/точность округления: что удалось подтвердить
Ошибка или замечание: ...

Не меняйте сами показатели ради обезличивания: заменяйте только идентификаторы/названия. Для скриншота обрежьте лишние сведения. Не присылайте .env, Client secret, access/refresh-токены, oauth.json, URL скачивания Google, полный архив данных или всю приватную аналитику.

Эта пара значений помогает проверить числовой масштаб, но задержка, округление и разные периоды могут сделать результат неоднозначным. При неоднозначности не вводим автоматический пересчёт. Если понадобится точный оригинальный CSV, обсудим отдельный безопасный способ — без секретов в чате.

## Этап 7. Проверить историю после остановки
После сохранения отчёта дождитесь завершения действий, остановите TubeStudio новым батником, запустите снова. Во вкладке «Показы и CTR» откройте тот же снимок из локальной истории. Он должен сохранить дату, строки и значения. Не нажимайте для этого «Загрузить и сохранить CSV» повторно: это создаёт новый снимок, не открывает старый.

Зачем: отдельно проверяем, что локальная история работает после перезапуска, а не только пока данные находятся в памяти вкладки. Совпадение версии/одного отчёта не закрывает доход, географию, несколько каналов, A/B и весь пункт 12.
