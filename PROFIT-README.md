# v0.12.71-preview.1 — сохранённые тарифы в калькуляторе

Автоматический режим снова принимает usage.json с pricingV1. Новые операции считаются по сохранённым до вызова тарифам и объёмам; текущие настройки их не переоценивают. Старые строки берутся только из pricingV1.legacy, а не из общих совместимых счётчиков: двойного включения нет. Для старого журнала без pricingV1 прежний расчёт не изменён.

- Основание costBasis:1 сохранено для legacy; costBasis:2 содержит старые строки, новые операции и accountingComplete. Внешняя версия снимка прибыли остаётся 2. Старые корректные v1/v2 читаются без миграции и без выдумывания исторических тарифов.
- Разные провайдеры и задачи одного ID — отдельные новые операции. Текст, изображения, аудио, TTS и поиск сохраняют свои тарифные снимки. В интерфейсе есть отдельный известный subtotal новых операций; старые оценки подписаны отдельно.
- Неизвестная цена/объём не становится нулём. Известная ошибка записи учёта также делает итог неполным: прибыль, маржа и окупаемость null. Локальный повтор записи не вызывает AI; сохранённый неполный расчёт после восстановления сам не меняется.
- costsHash включает основание, операции и статус полноты. Изменение учтённых данных, использованной legacy-ставки или дня UTC требует нового предпросмотра. Изменение неиспользованной текущей ставки не переоценивает captured-only основание. Хеш — не подпись и не счёт провайдера.
- JSON/Markdown и общий приватный ZIP сохраняют полное основание. В UI показаны первые 50 новых операций с тарифом и объёмом; это ограничение отображения, не усечение экспорта.
- usage.json до 8 МиБ, до 10 000 операций; legacy-строки до 1000. Сам снимок прибыли ограничен 2 МиБ: проверка ДО записи, превышение даёт 413 без сохранения/усечения. Сохраните журнал отдельно и используйте ручной режим со сверенными расходами.
- Если старых AnyModel-строк нет, общая ставка legacy в основании равна 0 как неприменимая. Это не нулевая цена новых операций: каждая имеет собственный тариф.

Не добавлены: получение счетов, атрибуция расходов по проектам, архив месяцев, устойчивый pending после падения процесса, полный учёт ошибок/отмен/повторов, запрет неизвестного тарифа перед отправкой или согласие warn. Нынешний бюджет не является гарантированным общим потолком. Реальные провайдеры и Windows требуют отдельной приёмки.

# v0.12.38-preview.1 — проверяемое основание расходов

Статус: предварительные тестовые исходники, не принятый релиз. Браузерная регрессия и визуальная приёмка ещё не выполнены. Версия тестовой сборки — v0.12.38-preview.1; последняя полностью проверенная здесь версия — v0.12.37. Инструкции отдельной проверки: LOCAL-CHECK-v0.12.38-preview.1.md.

## Что изменено
В режиме учёта всей установки раскройте **Проверить токены, ставки и формулы**. Для каждого AnyModel ID показаны балансовые токены, ставка USD / миллион и сумма. Если тот же ID есть в текстовом учёте или изображениях, эти счётчики показаны отдельно, но их прямые расходы не прибавляются повторно. Старый журнал не позволяет восстановить смешанное использование одного ID: требуется ручная сверка.

Для прямых моделей показаны input/output, число вызовов либо изображений, первое подходящее правило цены и формула. Нет подходящей ставки — стоимость неизвестна, не нулевая. Отсутствие активности может дать учтённый ноль, но не подтверждает бесплатность. Произвольные поля журнала в основание не копируются.

Сохранение в режиме workspace-month теперь требует costsHash из GET /api/profit/workspace-costs. Сервер перечитывает расходы и сравнивает основание: изменение записанных счётчиков, применённых ставок, покрытия или дня UTC даёт 409 с предложением обновить расходы. Отсутствующий хеш — 400. Время чтения внутри одного дня само по себе не инвалидирует основание; новый снимок хранит время повторного чтения. Хеш не является цифровой подписью, подтверждением прочтения или доказательством счёта провайдера. Изменение неиспользуемой настройки или произвольного поля журнала не меняет основание.

Новые снимки version: 2 сохраняют costBasis и reviewHash внутри workspace; ручной режим сохраняет workspace: null. JSON/Markdown и общий ZIP содержат сохранённую детализацию. Открытие не перечитывает текущие ставки/журнал. Старые v1 остаются без изменения: подробное историческое основание не восстанавливается из текущих настроек. Чтение v2 проверяет хеш, формулы и соответствие результата. Ограничения: до 1000 исходных записей суммарно, ID до 300 символов; превышение даёт ошибку, не усечение. Снимок до 2 МиБ; обычные файлы/каталог, без symlink; новые файлы 0600, каталог 0700 на поддерживающих это ОС. Более 5000 UUID-файлов требуют ручного обслуживания истории после резервного копирования.

MCP принимает v2, но его прежняя opt-in проекция возвращает только период и итоги — не журнал, токены, правила ставок или новую детализацию. Ограниченный токен Chrome доступа к финансовым маршрутам не получает. Новые права, AI, OAuth, получение счетов, атрибуция по каналам/проектам и восстановление прошлых месяцев не добавлены. Это сценарная оценка USD, не реальные выплаты и не бухгалтерская чистая прибыль.

Проверки preview: проверка типов и production-сборки трёх workspace прошли; **575 модульных тестов**, ошибок 0. Файловая проверка Windows на Linux прошла. Браузерные проверки, визуальная приёмка и нативный запуск Windows не выполнены.

Полная браузерная регрессия, визуальная проверка и нативная Windows-приёмка не выполнены. Архив preview — только для отдельной проверки, не готовый стабильный v0.12.38.

# Калькулятор прибыли — v0.12.7

## Назначение
Рабочее пространство → Калькулятор прибыли. Это арифметический сценарий в USD, не реальные выплаты YouTube, не подтверждение монетизации и не бухгалтерская чистая прибыль. Выручка и затраты не загружаются из банковских счетов, кабинетов провайдеров или OAuth. Нейросеть и YouTube не вызываются.

## Ручной режим
1. Оставьте «Все расходы вручную».
2. Укажите период, просмотры за него и RPM (USD дохода на 1000 просмотров). Просмотры и RPM должны соответствовать одному периоду и охвату; для Shorts и длинных видео с разными ставками создавайте отдельные расчёты.
3. Укажите AI-затраты и прочие траты в USD. Начальные нули — только ваше допущение; значения нужно проверить. Включите монтаж, комиссии, подписки, налоги и другие расходы сами.
4. Нажмите «Рассчитать и сохранить».

## Учёт текущего месяца TubeStudio
Выберите «Учёт TubeStudio — текущий месяц UTC». Показываются период с первого числа до сегодняшней даты UTC, точное время снимка, цена балансовых токенов и ограничения. Это ВСЯ установка, не один проект, ролик или канал. Введите суммарные просмотры и согласованный RPM за тот же период и охват. Для иного периода/одного проекта используйте ручной режим.

- Берётся локальный usage.json после завершения очереди записей учёта. Сервер перечитывает журнал при сохранении и проверяет costsHash: при изменении основания требуется обновить расходы и снова проверить их. Полученная версия фиксируется в результате.
- AnyModel: сумма всех полей am, включая озвучку, web-search и записи без строки llm/images. Один ID не считается повторно как текст и картинка. Стоимость = балансовые токены × anymodel.usdPerMillion / 1 000 000 из текущих Настроек.
- Балансовые токены сами могут оцениваться программой по коэффициентам; это не подтверждение фактического списания и не история фактических тарифов. Смена ставки меняет новый расчёт, но не старые снимки.
- Прямые модели без записи в am: input/output × цены за миллион или число картинок × цену картинки. Используется первая подходящая подстрока из Настройки → Бюджет → цены. Нулевая настроенная ставка — допущение, не доказательство бесплатности. Суммы прямых моделей закрепляются в снимке.
- Неизвестная ставка даёт null, а не 0. Известная часть расходов показывается отдельно, итоговая прибыль, маржа и окупаемость не вычисляются.
- Если usage.json отсутствует или относится к иному месяцу, текущие расходы считаются неизвестными. Старый журнал не сбрасывается. Повреждённый JSON/структура/отрицательные значения дают ошибку без изменения журнала; доступен ручной режим.
- Пустой корректный журнал текущего месяца означает лишь отсутствие учтённой активности, а не отсутствие реальных расходов. Внешние и пропущенные траты добавляйте в «Прочие затраты», не дублируя уже включённые.
- Старый журнал не разделяет прямые и AnyModel-вызовы одного и того же ID. При таком смешанном использовании сверяйте счета и используйте ручной режим. Учёт по проектам и восстановление прошлых месяцев этим выпуском не реализованы.
- При смене месяца между предпросмотром и сохранением программа предложит обновить данные, а не подменит период молча.

## Формулы и крайние случаи
- Выручка = просмотры × RPM / 1000.
- Указанные затраты = AI + прочие.
- Оценка прибыли = выручка − указанные затраты; отрицательное значение — убыток в этом сценарии.
- Маржа = прибыль / выручка × 100%; при нулевой выручке не определена.
- Просмотры до окупаемости = округление вверх (затраты × 1000 / RPM). При нулевых затратах — 0; при нулевом RPM и положительных затратах окупаемость недостижима.
- При неизвестной части расходов итог не выдаётся за полный. Предельные числа, не помещающиеся в точный/конечный числовой диапазон, не выводятся как Infinity или достоверная окупаемость.
- Расчёт не округляется до центов на промежуточных шагах; в интерфейсе USD показаны до 4 знаков после запятой, JSON хранит числовую точность JavaScript. Микросуммы могут визуально округляться до нуля.

## История и экспорт
Каждый расчёт создаёт отдельный снимок DATA_DIR/profit-runs/<UUID>.json. Он содержит введённые числа, период, результат, а в режиме учёта — применённую ставку, суммы и предупреждения. Изменение формы, журнала и цен его не пересчитывает. Для пересчёта явно сохраните новый результат.

История показывает последние 50 снимков, не удаляя более старые файлы. Открытие локальное. Доступны копирование, Markdown и JSON; отдельного импорта JSON в калькулятор нет. Общий ZIP-перенос включает profit-runs. Экспорты содержат финансовые данные — храните приватно. Системные ключи, OAuth-токены и произвольные поля журнала в снимок расчёта не копируются.

## Обновление
Завершите задания, остановите сервер и сохраните резервную копию текущей папки, данных, .env и своих промптов. Скопируйте содержимое tubestudio из архива исходников в текущую папку с заменой файлов, не создавая вложенную tubestudio. Не удаляйте .env, data или apps/server/data. Затем update-windows.bat, дождитесь успешного завершения и обновите браузер Ctrl+F5. Требуется установленный Node.js.

Исходники можно редактировать в обычной IDE. После изменений: npm run typecheck и npm run build. Полные PDF/DOCX остаются историческими v0.11; Windows-ярлык и реальные провайдеры требуют отдельной приёмки.
