## Новые проверки

Согласуемый план, строгие схемы, отсутствие сети при создании/просмотре, неизменяемый список шагов после создания, защита повторного подтверждения. Модель каждой роли назначена явно. Изменение плана/сообщения/ревизии отклоняет устаревший просмотр. Две конкурирующие отправки дают одну резервированную попытку.

Вопросы удерживают тот же шаг; пустое продолжение блокируется. Ответ на вопросы получает прежнюю переписку и инструкции процесса. Завершённый результат ожидает принятия. Принятие не вызывает AI, не сохраняет в проект и не запускает следующий шаг. Авторский шаг использует точную авторскую модель, а не рутинную; получает ранее принятые шаги. Пустой авторский результат нельзя принять. Повтор старого принятия не двигает процесс ещё раз.

Отмена до отправки не делает вызов. Прерванная попытка не повторяется сама. Пока попытка активна, разблокировка запрещена. Без явно подтверждённого риска оплаты повтор не разрешается; разрешение лишь возвращает возможность нового просмотра. Запись о неизвестной попытке сохраняется. Если ответ уже записан, повтор запрещён: сначала восстановление. Имитированный отказ записи контрольной точки после получения/сохранения ответа не требует новой генерации — восстановление находит ровно эту попытку по parentId/hash/роли. Исходящие API при восстановлении не вызываются.

Явная привязка ветки после смены моделей сохраняет принятые результаты и их исходную атрибуцию; чужая переписка отклоняется. Повреждённый порядок контрольных точек, symlink/hardlink и traversal не считаются пустым планом.

Через HTTP/интерфейс: создание плана без AI; вопросы → ответы → принятие → отдельный вызов авторской модели → финальное принятие; открытие ранее принятого ответа без генерации; снятие подтверждения при правках; закрытие/открытие с сохранением текущего шага и без повтора; остановка и отдельное согласие для новой попытки. Тёмная тема 1440 и светлая 1024: нет pageerror и горизонтального переполнения, снимки просмотрены.

## Диагностика и ограничения

Первый адресный UI-прогон дал 24/25: тест открытия принятого шага искал одинаковый текст в ещё не сменившейся переписке. Исправлено только ожидание теста: сначала дождаться сохранённого ID выбранного диалога, затем проверить текст. Проверки открытия правильного результата и отсутствия нового вызова не убраны. Диагностический лог сохранён; адресный набор и полный настольный прогон выполнены заново, результаты не склеены.

Нет живой приёмки внешних API, YouTube или качества модели. Используются синтетические данные и изолированный loopback. Нет настоящей Windows, сетевой/FAT ФС и отключения питания. Очередь защищает один сервер, не параллельный импорт/ручную правку/несколько серверов с общим DATA_DIR. Имитация отказа записи не является испытанием аппаратного диска. Нет автоматического выделения плана из файла, ветвления и медиа-цикла; порядок подтверждает пользователь. Остаются прежние лимиты диалога 10 ответов/100 000 символов, а не обещание любого числа уточнений.
