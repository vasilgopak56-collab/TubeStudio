# Reach Basic: проверка единицы CTR

## Статус
Проверка официального определения выполнена для текущей v0.12.43-preview.1. Единица числового представления CSV **не подтверждена**. Код приложения, версия, формат снимков и действующие правила показа не изменены. Реальные Google/OAuth-запросы и платные API не запускались; новая регрессия не нужна для этой записи документации и не заявляется.

## Официальное определение
Источник: https://developers.google.com/youtube/reporting/v1/reports/metrics?hl=en#reach-metrics

Для video_thumbnail_impressions_ctr в загруженном определении указано:
“The percentage of impressions that resulted in a click to watch the video. This is calculated as clicks divided by impressions.”

Определение описывает смысл метрики, но загруженный фрагмент не содержит числового примера CSV, явного диапазона или инструкции о множителе 100. Поэтому по одному слову percentage не выбирается способ числового преобразования. Оценки и примеры сторонних сервисов не заменяют проверку формата Google.

## Что проверено в текущем коде
- Поддержан только channel_reach_basic_a1 и пять точных столбцов.
- Исходное числовое значение CSV сохраняется как ctrApi, без умножения/деления и без знака процента в интерфейсе/Markdown.
- Парсер принимает только конечное неотрицательное десятичное значение не больше 100. Этот технический предел сам по себе не доказывает единицу CSV.
- При неизвестных/нулевых показах либо неправильном CTR значение считается неизвестным, а не известным нулём.
- Интегральный CTR, восстановленные клики, результаты вариантов A/B и автоматический победитель не вычисляются.
- Изменение отображения старых снимков без доказанной единицы не выполнялось.

## Минимальные данные для следующего шага
Нужен только обезличенный фрагмент **оригинального Reach Basic CSV**, не общий ZIP TubeStudio и не экспорт Studio с другой схемой:

1. Точная строка заголовков и 1–3 строки за одну дату. Сохраните исходное написание чисел/десятичный разделитель; не округляйте и не пересохраняйте через Excel.
2. Замените channel_id/video_id стабильными тестовыми идентификаторами и отметьте замену. Один и тот же исходный ID должен получать один и тот же тестовый ID. Не присылайте названия каналов/видео.
3. Для одной строки с ненулевым числом показов — контрольный CTR из исходной аналитики того же видео/дня и точность округления. Дата Reach CSV относится к America/Los_Angeles; сравнение с другим часовым поясом или периодом не принимается как доказательство.
4. Укажите тип channel_reach_basic_a1 и дату/период сравнения. Если контрольное значение отсутствует, проверка единицы останется открытой.

Не присылайте .env, access/refresh-токены, Client secret, oauth.json, URL загрузки Google, полный приватный отчёт или резервную копию. Если безопасно подготовить фрагмент нельзя, не передавайте его: можно провести ручную сверку локально и сообщить только обезличенную пару исходное число CSV / контрольный CTR с датой и охватом.

## Критерий принятия
Должно быть однозначно установлено, что исходное число означает процентные пункты, долю либо другой документированный формат. Простое совпадение порядка величины недостаточно: учитывать точный день/видео, задержку и округление. При неоднозначности сохраняется исходное отображение без %. Даже после успешной сверки это не приёмка всего Reporting/OAuth, всех каналов, Windows или A/B.


## Практический первый шаг через имеющийся интерфейс
Подробная инструкция владельцу установки: POINT-12-STEP-BY-STEP.md. Для начальной ручной сверки не нужно добывать исходный CSV: число CTR API уже сохранено без пересчёта в таблице и ctrApi в Reach JSON. Можно переписать только 1–3 обезличенные строки и контрольный CTR того же видео/дня из Studio. Это не оригинальный CSV и не доказательство его текстового формата; при неоднозначной сверке единица остаётся неподтверждённой. Не предлагайте пользователю копировать токены/URL Google из Developer Tools ради получения файла.
