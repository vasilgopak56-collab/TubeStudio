# TubeStudio v0.12.48-preview.1 — от найденного видео к гипотезе ниши

Эта сборка включает **оба этапа**: кандидаты/замеры/собственный ракурс из .47 и новое сравнение каналов. Ставить .47 перед .48 не требуется. Это preview: проверено на Linux с искусственными ответами провайдеров; нативный запуск этой версии на вашем Windows ещё предстоит проверить.

## Что теперь связано в один процесс

**Поиск → сохранённое исследование → кандидат → выбранные каналы → проверенные вручную примеры → гипотеза ниши → свой ракурс → проект → сценарный бриф.**

Сохранение, открытие истории, просмотр проекта и применение брифа не запускают AI. Генерация сценария — отдельное действие с выбранной моделью и возможной оплатой.

## 1. Установить отдельно, сохранив рабочую версию

Ничего не удаляйте из рабочей `Версия_20` (или папки .47, если уже перешли на неё). Выберите новую, ещё не занятую папку; ниже пример `Версия_22`. Не распаковывайте новый исходный ZIP поверх неё.

1. В рабочей программе завершите задания. Сделайте **Настройки → Данные → Экспорт всех данных**. ZIP храните у себя: в нём могут быть OAuth-токены и приватные тексты. Отдельно сохраните `.env`, поскольку общий ZIP его не включает.
2. Остановите запущенные копии через `stop-windows.bat` **из папки каждой запущенной установки**. Если тестовая копия запущена вручную в командной строке — остановите её `Ctrl+C`. Закрыть вкладку браузера недостаточно. При отказе безопасной остановки не продолжайте копирование и пришлите сообщение; не завершайте все процессы Node.js подряд.
3. Распакуйте новый ZIP в отдельную папку, например `D:\Desktop\Программы\TubeStudio\Версия_22`. Внутри будет папка `tubestudio` с `package.json`.
4. При остановленных программах **скопируйте**, не перемещайте:
   - `Версия_20\tubestudio\.env` → `Версия_22\tubestudio\.env`;
   - `Версия_20\tubestudio\apps\server\data` → `Версия_22\tubestudio\apps\server\data`;
   - если меняли промпты, содержимое `Версия_20\tubestudio\apps\server\prompts` → соответствующую папку новой версии. Для полного сохранения ваших правок подтвердите замену файлов промптов; исходные промпты новой версии останутся в скачанном исходном ZIP.

   Если уже работаете в .47, вместо `Версия_20` берите папку вашей рабочей .47. Эти пути относятся к вашей ранее проверенной установке с `DATA_DIR=./data` и запуском Windows-ярлыком. Если в `.env` теперь задан **абсолютный или другой путь** DATA_DIR/PROMPTS_DIR — сначала уточните его. Две копии нельзя запускать одновременно с одним каталогом данных. Секреты `.env` в чат не присылайте.
5. В новой папке `tubestudio` откройте командную строку и выполните по очереди:

   ```bat
   npm ci
   npm run build
   ```

   Рекомендуется Node.js 24. При ошибке остановитесь и пришлите её. Не запускайте `npm audit fix --force`. Предупреждение npm о разрешении install-скрипта esbuild отдельно от результата сборки: не нужно разрешать все пакеты вслепую. Чистая контрольная установка этой поставки проверялась с `npm ci --ignore-scripts`, затем сборкой.
6. В **новой** папке запустите `create-desktop-shortcut.bat` обычным пользователем, не от администратора. Дождитесь подтверждения правильного пути `Версия_22\tubestudio\windows\launch.ps1`.
7. Запустите новый ярлык. Проверьте версию **v0.12.48-preview.1**, адрес обычно `127.0.0.1:8787`, сохранённый расчёт **200 $**, календарь и историю Reach. Открытие старого Reach не требует повторной авторизации Google. Ключи берутся из скопированного `.env`; действительность OAuth зависит от сохранённых токенов и Google.
8. Старую папку и резервную копию пока оставьте. При возврате остановите новую копию, заново создайте ярлык из старой и запустите её. Новые данные .48 автоматически назад не переносятся. Старые сборки могут не включать новый каталог сравнений в свой ZIP — экспорт новых данных делайте из .48.

**Итог:** остановить → резервная копия → новая отдельная папка → скопировать `.env`, реальные данные и свои промпты → `npm ci` / `npm run build` → новый ярлык. Копирования одного `.env` недостаточно для проектов и истории.

## 2. Первый исследовательский проход: history

1. Откройте **Исследование → Outliers и обложки**.
2. Выберите **History · строгий отбор 50×**. Это заполняет настройки, но не отправляет запросы. Проверьте язык `en`, тему `history`, период и порядок поиска. Если нужен другой язык/страна — измените до запроса.
3. Нажмите **Исследовать**. Программа загружает одну страницу до 50 поисковых результатов; это не весь YouTube. Если включена база Outlier, она собирается только для первых выбранных каналов страницы. Стоимость указана на кнопке; повторы/диагностика отдельно. Это Data API, не vidIQ.
4. Просмотрите результат и условия отбора: просмотры, подписчики, собственный Outlier, длительность/возраст. Показатель неизвестен — не означает 0 и не проходит требование известного числа. Нет результатов под строгими условиями — не доказательство отсутствия ниши. Можно ослабить пороги локально, не объявляя пустую выборку ошибкой.
5. Откройте интересное видео на YouTube: действительно ли оно историческое, что именно обещает, какой формат и аудитория? Не выбирайте по одному числу.
6. Нажмите **В кандидаты**. Сохраняются исходный снимок и ссылка, а не выдуманный текущий рост. Повторное добавление того же ID сохраняет первый источник.

## 3. Проверить похожие/конкурентные каналы

1. В карточке кандидата нажмите **Сравнить каналы**. Откроется блок **3. Сравнить каналы → проверить тему → гипотеза ниши**. Пока читаются только локальные данные.
2. Выберите от одного до трёх каналов из исходной страницы поиска. Канал источника выбран первоначально. Это **ваш выбор потенциальных конкурентов**, не автоматическое доказательство одинаковой аудитории. Канал вне исходной страницы добавить сюда нельзя: для него сначала нужно отдельное исследование и кандидат.
3. Введите узкие фразы заголовков через `;`. Например: `ancient rome; roman daily life`. Режим «хотя бы одна» находит любую фразу, «все» — каждую. Не оставляйте только `history`, если хотите проверить конкретную тему.
4. Установите пороги просмотров и собственного Outlier. По умолчанию нового сравнения **50 000 / 20×**; пресет первоначального поиска 50× не переносится сюда автоматически. Если проверяете ту же строгую гипотезу, поставьте **50×** вручную.
5. Выберите группу длительности при необходимости. `До 180 секунд` не равнозначно подтверждённому Shorts: это только техническая группа по длительности.
6. Прочитайте и отметьте согласие на свежие запросы YouTube. Нажмите **Собрать сравнение каналов**. Для n каналов базово до **1 + 2n единиц**, максимум 7 для трёх: один запрос каналов и до двух на канал (страница загрузок + метаданные). Для пустой страницы второй запрос не нужен. Повторы/отдельная диагностика сверх этого. Автоматического перехода к следующим страницам нет.
7. Дождитесь сохранённого снимка. У каждого канала посмотрите время страницы/счётчиков, количество ID, наличие продолжения, недоступные метаданные. Пустая успешно полученная страница, недоступные загрузки и не возвращённый канал показаны по-разному.
8. Фильтр **Показать видео** позволяет оставить словесные совпадения, видео выше числовых порогов или отмеченные в текущей форме. Он меняет только показ, не снимок/квоту/сохранённую сводку. Скрытые строки не считаются нулевыми.
9. Посмотрите ролики по ссылкам. Отметьте **Подходит теме (проверено вручную)** только у действительно подходящих. Можно отметить и видео без совпадения фраз, если вы проверили смысл. Неотмеченное означает «не подтверждено», не «опровергнуто».
10. Раскройте основание Outlier: какие видео вошли в базу, медиана, причины исключения. Заголовок похож, но аудитория другая — не считайте конкурентным примером только из-за слова.

### Как читать сводку

- До сохранения ручных отметок состояние **«Тематическая проверка ещё не сохранена»**, даже если слова совпали.
- В сводку поддержки входят только **подтверждённые по теме** видео с **известными** показателями выше заданных порогов.
- Много подходящих роликов одного канала всё равно дают **один канал**, не несколько.
- Несколько ID каналов с примерами — ограниченное наблюдение, а не доказательство независимых владельцев, устойчивого спроса или будущего успеха.
- Неизвестные просмотры/длительность/база не подменяются нулём. Outlier рассчитывается только при достаточной базе.

## 4. Зафиксировать гипотезу и свой ракурс

1. В **Гипотеза ниши** напишите, для кого и о чём хотите делать собственные видео. Например: «История повседневной жизни обычного римлянина, рассказанная через воду, еду и жильё». Это пример формулировки, не найденная нами ниша.
2. В **Ограничения и контрпримеры** запишите: маленькая выборка, старый ролик, разная длительность, возможный единый владелец каналов, неподходящие примеры. Не скрывайте опровергающие наблюдения.
3. Нажмите **Сохранить проверку темы**. Сводка обновится только по сохранённому решению. Исходный снимок не переписывается. Если другая вкладка успела сохранить новую версию, будет конфликт: сначала откройте актуальную версию, затем повторите правки осознанно.
4. Вернитесь к карточке кандидата → **Выбрать ракурс и подготовить бриф**. Укажите свою тему, узкую нишу, оригинальный ракурс минимум 10 символов, заметки, профиль и длительность. **Сохраните бриф**, затем **Создайте проект из брифа**.
5. Вернитесь к сравнению и нажмите **Закрепить сравнение в проекте**. Нужны сохранённая гипотеза минимум 10 символов и хотя бы один подтверждённый по теме ролик. Можно закрепить и отрицательную/неубедительную проверку: числовые ограничения останутся видны, это не знак «ниша одобрена».
6. Закрепляется новая заметка проекта с источниками, ручным решением и расширенным сценарным брифом. Повтор той же версии не создаёт дубль. Изменённое сохранённое решение можно закрепить как **новую версию**, старые остаются прежними.

## 5. Перейти к сценарию без копирования чужого ролика

1. Нажмите **К сценарию со сравнением**.
2. Откройте блок **Бриф из исследования** и проверьте тему, источники, гипотезу, ограничения. Ссылки на успешные ролики — **референсы подачи, не источники исторических/научных фактов**.
3. Нажмите **Применить бриф к форме** и подтвердите замену текущего черновика. Без подтверждения поля не заменяются; генерация не запускается.
4. Проверьте язык, модель, длину, тон и заметки. При желании добавьте подтверждённые источники фактов. Непроверенные утверждения должны быть отмечены `[ПРОВЕРИТЬ]` или удалены.
5. Только после этого отдельно запускайте генерацию сценария. Затем проверка фактов/структуры → редактура → озвучка → план сцен → собственный визуальный стиль → упаковка → календарь. Массовая генерация картинок и её расходы не запускаются этим исследовательским процессом.

Профили из .47 сохраняются: история — ориентир 140 слов/мин, психология — 145, общий рассказ — 150. Это планирование текста, не гарантированная длительность аудио. Документы пользователя использованы как методические ориентиры, без копирования чужого бренда, обязательного пугающего вступления или выдуманных исследований.

## 6. История, приватность и границы

- До 100 кандидатов, до 200 последних ручных замеров у каждого, до 100 сравнений. Новое сравнение не обновляет старое. Отмена/ошибка не заменяет открытый снимок; уже отправленные запросы могли потратить квоту.
- Один снимок сравнения — до трёх каналов и одной страницы до 50 загрузок каждого. Более старые тематические хиты могут не попасть на страницу.
- Словесные совпадения — нормализованные целые фразы в заголовке; без перевода, склонений, просмотра содержания или AI-семантики. Они не определяют аудиторию.
- Собственный Outlier — просмотры цели / медиана минимум трёх других подходящих видео того же канала и группы длительности, возрастом от 48 часов; цель тоже должна быть не моложе 48 часов. Само видео исключено, медиана должна быть >0. Возрастные окна не выровнены. Это не закрытая формула vidIQ.
- Средний VPH исходного поиска, интервальный рост кандидата и накопленные просмотры нового сравнения — разные вещи. Сравнение не измеряет текущий рост автоматически. Для роста нужны два ручных замера кандидата минимум через час, лучше 6–24 часа.
- Публичный поиск не даёт CTR, удержание, доход конкурента или точный поисковый спрос. Соответствие формату не подтверждает историческую/научную достоверность.
- Источники лежат в `DATA_DIR/research-comparisons/<id>.json`, ручное решение отдельно `<id>.review.json`; входят в общий ZIP .48 вместе с кандидатами/проектами. JSON-кнопка экспортирует сохранённый отчёт, не несохранённую форму.
- Удаление сравнения не удаляет закреплённую версию проекта; она продолжает читаться без API. Удаление проекта отдельно удаляет его материалы.
- Ключи, OAuth и приватные данные пользователя не входят в поставляемый исходный ZIP. Пользовательский **резервный ZIP** может содержать секреты, не публикуйте его. Chrome-расширению новые данные не открываются; отдельный read-only MCP-доступ к сравнению не добавлялся.
- Файловые защиты и очередь записи относятся к одному серверному процессу, не к конкурентной записи двумя установками. Резервное копирование/импорт делайте после завершения заданий; полная файловая копия — при остановленном сервере.

Отчёт: `RELEASE-v0.12.48-preview.1.md`, технические результаты `docs/checks/research-comparison-v0.12.48.json`. Документы .47 и более ранних версий оставлены в архиве как история, не как актуальный отчёт .48.
