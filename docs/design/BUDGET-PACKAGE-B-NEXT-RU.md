# Актуализация после .73

В .72 подключён block-барьер перед фактической отправкой. В .73 готов только серверный протокол одноразового согласия: брокер, приватные решения и синтетическая SSE-пауза/продолжение. Платные адаптеры и окно решения ещё не подключены; warn сохраняет прежнее поведение. Не считать приведённый ниже исторический план реализованным целиком. Точный остаток — REMAINING-BEFORE-LIVE-TESTS-RU.md; границы .73 — RELEASE-v0.12.73-preview.1.md.

# Состояние после .71

Часть 2 уже сохраняет тариф новых успешных операций; это не durable финансовый ledger всех исходов. Карта ниже исторически составлена до .70: старый поздний TTS-учёт и fallback-оценки в новых записях заменены адаптерными снимками. В .71 интеграция прибыли выполнена через основание с операциями и сохранёнными тарифами; неизвестный итог не выдан за полный. Приоритет далее: block/warn до фактической отправки и обработка неизвестных исходов. Точный актуальный остаток — REMAINING-BEFORE-LIVE-TESTS-RU.md.

# Пакет B: следующая часть — проектирование, не реализованная возможность

Правила подтверждены пользователем: неизвестная цена запрещена в block; в warn требуется отдельное согласие. Часть .69 затронула только отчёт и сравнение границы. Ниже — карта обязательной интеграции перед реализацией следующей части.

## Реальные точки вызова

| Путь | Где нужно проверять фактический маршрут | Риск |
|---|---|---|
| Текст | llm.ts: callAnthropic, callGemini, callAnymodel; raw/plan | Есть резервные модели, временное исключение, повторы JSON; начальная проверка до plan недостаточна |
| Веб-ресёрч | geminiGrounded / directGrounded | Текст и дополнительный поиск могут иметь разные тарифы; общий catch не должен проглотить финансовый запрет |
| Картинки | imageGen.ts: steps, openai/gemini/amImage | Запрос редактирования multipart и генерация — разные задачи; общий catch сейчас переходит на запасной путь |
| Озвучка | runTts / speakWithFallback / previewVoice | Модель может измениться по языку или после ошибки. Проба голоса тоже платная. Части запускаются пачками, общий учёт записывается позднее |
| Распознавание | audioStoryboard.ts: отдельная бюджетная проверка и am-токены | Не проходит через обычный raw текста; отдельный формат входа и расчёт |
| AnyModel | anymodel.ts: amChat/amImage/amSpeech и каталог | Отсутствующие коэффициенты заменяются приблизительными; их нельзя объявить достоверно известным тарифом строгого запуска |
| HTTP/retry | fetchRetry, очереди провайдеров | Проверка до очереди не гарантирует актуальное состояние перед отправкой. Retry и fallback не должны обходить финансовый отказ |

Это карта найденных путей, не доказательство охвата абсолютно всех запросов; перед изменением необходим поиск всех генеративных fetch/SDK и проверка публичных экспортов.

## Контекст задачи и согласие

- startJob создаёт новый runTask-контекст с signal/jobId/onQueue. Новое финансовое согласие нельзя потерять при этом переходе. withTaskSignal сохраняет родительские поля, но этого недостаточно без явного проектирования.
- Согласие привязать к конкретному маршруту/модели/задаче и снимку настроек/тарифа. Изменение данных, истечение срока, отмена и другой пользователь не должны повторно использовать разрешение.
- Для SSE недостаточно выбросить ошибку и предложить повтор всего POST: часть задачи могла уже оплатиться. Нужна явная пауза до конкретного неизвестного запроса либо точка продолжения, не скрытый перезапуск.
- Учесть клиенты с собственным обработчиком событий, не только общий useJob. Отсутствие подписчика/уход со страницы/Стоп должны завершать ожидание без позднего платного вызова.
- Финансовые ошибки отдельного типа не должны превращаться в обычную ошибку провайдера и запускать fallback. Не использовать универсальный автоматический replay HTTP-запроса после подтверждения.
- Не делать постоянный флажок «разрешать всё неизвестное» заменой отдельного согласия.

## Запись цены операции

- Новый неизменяемый снимок: ID операции, время UTC, провайдер, маршрут, модель, задача, единицы, тариф/источник/хеш версии и оценка. Отдельно известность тарифа и полнота объёма, не один булевый «всё точно».
- Выделить ожидаемую оценку, фактические возвращённые единицы и внешний счёт. Успех генерации не удостоверяет счёт, а HTTP-ошибка не доказывает отсутствие оплаты.
- Старые llm/images/am агрегаты не содержат надёжного происхождения. Не приписывать им новый ID провайдера или исторический тариф. Проверить смешанный model-ID, отдельные am-записи TTS и отсутствие двойного счёта.
- Очередь usage.ts сейчас подавляет ошибку записи; провайдер уже мог выполнить работу. Исправление должно сохранять результат/предупреждение без повторной генерации ради восстановления журнала.
- Продумать восстановление, backup allowlist, предел размера и истории, повреждённый/отсутствующий журнал, переход месяца. Чтение с fallback-пустым журналом не разрешает строгое обещание бюджета.

## Резервирование — отдельное продолжение

Не вводить фиктивный жёсткий потолок, пока неизвестны верхние оценки, параллельность, время удержания и восстановление. Очередь одного процесса не блокирует другую установку. Нужны явные правила для pending/committed/unknown outcome, отмены после отправки и падения процесса. Это не реализовано .69.

## Приёмочные проверки следующей части

1. Каждый фактический провайдер/задача с известным, нулевым и неизвестным тарифом.
2. Block до отправки; fallback не обходит запрет; metadata остаются отдельными.
3. Warn без согласия не отправляет, согласие точное и ограниченное, повтор/устаревание/отмена не переиспользуют его.
4. SSE-пауза не теряет уже полученные части и не перезапускает оплату; уход/timeout/нет подписчика безопасны.
5. Изменение тарифов не меняет снимки новых завершённых операций; legacy остаётся явно оценочным.
6. Ошибка записи после выполненной генерации не вызывает повторного провайдерного запроса.
7. Корректная неполнота на неизвестном исходе, TTS-частях, поиске и смешанных маршрутах.
8. Полный локальный настольный набор, затем отдельно согласованные живые проверки с маленьким бюджетом.
