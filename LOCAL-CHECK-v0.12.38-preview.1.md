# Отдельная проверка v0.12.38-preview.1

**Тестовые исходники, не принятый релиз.** Рабочую v0.12.37 не заменяйте. Здесь не выполнены браузерная регрессия, просмотр интерфейса и нативная Windows-приёмка preview. Новые автоматические браузерные сценарии детализации не включены в архив; ниже — ручной чек-лист и существующие тесты.

## 1. Подготовка
- Сохраните резервную копию рабочей установки отдельно и оставьте её без изменений.
- Распакуйте архив в **новую папку**, например `TubeStudio-preview`. Внутри неё откройте папку `tubestudio`, где лежит package.json.
- Не копируйте туда рабочие `.env`, `data`, OAuth, ключи или пользовательские промпты. Не импортируйте рабочий ZIP данных. Для этой проверки платные сервисы не нужны.
- Нужен актуальный Node.js LTS (рекомендуется 24). `npm ci` загружает зависимости из npm: это сетевой шаг установки, не вызов AI/YouTube.
- Откройте PowerShell в новой папке. Команды выполняйте по очереди. При ненулевом коде остановитесь; не продолжайте установку как успешную.

```powershell
node --version
npm ci
npm run typecheck
npm run build
npm run check:windows
```

Проверка Windows без `--diagnose` проверяет только файлы, не запускает сервер и не создаёт ярлык. `update-windows.bat` для тестовой проверки не требуется. Не меняйте рабочий ярлык.

## 2. Изолированный ручной запуск на Windows

В **отдельном окне PowerShell**, открытом в новой папке с package.json, выполните следующий блок. Он задаёт отдельный каталог и удаляет ключи только из окружения текущего окна и его дочернего процесса — не из Windows и не из рабочих `.env`. Сам Node запускается без загрузки `.env`. Порт 8798 должен быть свободен; приложение слушает только 127.0.0.1.

```powershell
$root = (Get-Location).Path
$env:DATA_DIR = Join-Path $root 'preview-test-data'
$env:PROMPTS_DIR = Join-Path $root 'apps/server/prompts'
$env:HOST = '127.0.0.1'
$env:PORT = '8798'
$names = @('ANYMODEL_API_KEY','YOUTUBE_API_KEY','YOUTUBE_API_KEY_2','YOUTUBE_API_KEY_3','GEMINI_API_KEY','LUMEAN_API_KEY','ANTHROPIC_API_KEY','OPENAI_API_KEY','GOOGLE_CLIENT_ID','GOOGLE_CLIENT_SECRET','APP_PASSWORD')
foreach ($name in $names) { Remove-Item "Env:$name" -ErrorAction SilentlyContinue }
node apps/server/dist/index.js
```

Откройте `http://127.0.0.1:8798/profit`. Не вводите реальные ключи и не подключайте Google. Для остановки нажмите Ctrl+C в этом PowerShell.

### Ручной сценарий — без журнала
1. Название: `Ручная проверка`; просмотры: 100000; RPM: 2.5; AI: 10; прочие: 40. Период задайте согласованно.
2. «Рассчитать и сохранить»: доход 250 USD, указанные затраты 50 USD, прибыль 200 USD, маржа 80%, окупаемость 20000 просмотров.
3. Измените RPM в форме: сохранённый результат и экспорт не должны меняться. Скачайте Markdown и JSON.
4. Перезагрузите страницу, откройте историю: результат прежний. Нулевой RPM с положительными затратами не даёт достижимую окупаемость.

## 3. Демонстрационный учёт — только в отдельной тестовой папке

Сначала остановите тестовый сервер Ctrl+C. Следующий блок выполняйте из той же новой папки с package.json. Он записывает **только два демонстрационных файла в preview-test-data**. Если вы уже вводили туда свои тестовые ставки/журнал, сначала сохраните их отдельно: эти два файла будут заменены. Никогда не меняйте пути на рабочую папку данных.

```powershell
$demoDir = Join-Path (Get-Location).Path 'preview-test-data'
New-Item -ItemType Directory -Force -Path $demoDir | Out-Null
$month = (Get-Date).ToUniversalTime().ToString('yyyy-MM')
$usage = @{
  month = $month
  llm = @{
    same = @{in=200; out=100; calls=2}
    'paid-text' = @{in=1000000; out=500000; calls=3}
  }
  images = @{same=2; 'paid-image'=3}
  am = @{same=1000000; 'web-search'=40000}
}
$settings = @{
  anymodel = @{usdPerMillion=2}
  budget = @{prices=@(@{match='paid'; input=3; output=6; image=0.2})}
}
$utf8 = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText((Join-Path $demoDir 'usage.json'), ($usage | ConvertTo-Json -Depth 10), $utf8)
[System.IO.File]::WriteAllText((Join-Path $demoDir 'settings.json'), ($settings | ConvertTo-Json -Depth 10), $utf8)
```

Снова выполните блок из раздела 2 для запуска. Не используйте обычный запуск рабочей установки.

### Проверка детализации и фиксации
1. Выберите «Учёт TubeStudio — текущий месяц UTC». Раскройте «Проверить токены, ставки и формулы».
2. Ожидается: AnyModel 1040000 балансовых токенов × 2 / 1000000 = **2.08 USD**; paid-text = **6 USD**, paid-image = **0.6 USD**; известные AI-затраты **8.68 USD**. У `same` показаны дополнительные текстовые/графические счётчики, но они не добавлены повторно.
3. Просмотры 100000, RPM 2, прочие 4 → доход **200 USD**, затраты **12.68 USD**, прибыль **187.32 USD**. Промежуточное округление до центов не применяется.
4. Раскройте «Сохранённое основание расходов». JSON должен иметь `version: 2`, `workspace.costBasis` и `workspace.reviewHash`; токены и применённые ставки соответствуют предпросмотру.
5. Измените RPM формы, затем экспортируйте JSON/Markdown: должен экспортироваться открытый снимок, не несохранённая форма.
6. Для проверки устаревшего основания оставьте старую вкладку открытой. В новой вкладке Настроек **тестовой установки** измените цену балансовых токенов с 2 на 3 и сохраните её. Не обновляя старую вкладку калькулятора, снова нажмите «Рассчитать и сохранить»: ожидается ошибка с предложением обновить расходы, без замены прежнего результата.
7. Нажмите «Обновить расходы», проверьте новые суммы и только затем сохраните новый снимок. Старый расчёт из истории должен остаться неизменным. Хеш проверяет соответствие, не подтверждает прочтение.
8. Отсутствующая ставка должна давать «Неизвестно», а не 0; неизвестная часть блокирует итог прибыли и окупаемость. Пустой корректный журнал — лишь отсутствие учтённой активности, не отсутствие реальных трат.
9. Старые v1 должны открываться без пересчёта; сообщение об отсутствии подробного основания не должно заменяться нынешними ставками. Для этой проверки используйте только отдельную синтетическую/обезличенную копию, не рабочий архив с OAuth.
10. Проверьте 1440 px и около 390 px, раскрытые блоки и длинные ID: без наложений и горизонтального скролла всей страницы. Снимки экрана не должны содержать ключи или рабочие финансовые данные.

## 4. Автоматические проверки

Модульные проверки:

```powershell
npm run test:unit
```

Их эталонная среда — Linux. Проверки symlink на Windows могут требовать возможностей ОС, которых нет у текущей учётной записи. Это ограничение среды, не повод отключать защиту или запускать весь проект с правами администратора. Для воспроизведения используйте подготовленную Linux-среду/WSL; точную причину отказа сохраните в отчёте.

### Пять существующих браузерных тестов калькулятора

Нужен установленный Chrome/Chromium. Укажите **реальный путь** к его исполняемому файлу в CHROME_PATH; пример пути ниже не гарантирует его наличие. Локальный тестовый сервер использует порт 8799, временные данные и моки вместо внешних запросов. Рабочее приложение/его порт не должны подменять тестовый сервер. Не запускайте несколько копий тестов параллельно.

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node --test --test-concurrency=1 --test-name-pattern="Прибыль:" tests/e2e/tools.test.mjs
```

Эти тесты покрывают существующие ручной режим, текущий месяц и отказ при смене журнала, неизвестную ставку, нулевой RPM/мобильную ширину и сохранение результата при ошибке. Они **не заменяют** недобавленные целевые тесты новой детализации, stale-ставок, новых файлов v2 и MCP. Ручной чек-лист выше также не заменяет всю регрессию.

Полный `npm run test:e2e` — отдельный шаг приёмки в подготовленной Linux-среде: часть исторических тестов содержит `/usr/local/bin/chromium` и `/data/...`, не все соблюдают CHROME_PATH. Не создавайте системные ссылки и не меняйте системные каталоги ради обхода этих ограничений; переносимость тестов требует отдельной доработки. Этот архив не заявляет готовый Windows-запуск полного E2E.
