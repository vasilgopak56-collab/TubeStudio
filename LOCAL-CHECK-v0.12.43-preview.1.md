# Обновление и проверка v0.12.43-preview.1

## На вашей Windows
1. Сохраните резервную копию данных и настроек вне папки установки. ZIP-перенос может содержать приватные данные/OAuth; никому его не отправляйте. .env сохраните отдельно, не присылайте его в чат.
2. Распакуйте архив. Обновите файлы программы в существующей папке tubestudio, но НЕ удаляйте .env и data. Не считайте закрытую вкладку остановкой сервера.
3. Запустите update-windows.bat из этой папки. Он пытается остановить только однозначно распознанный сервер этой установки; если принадлежность процесса не подтверждена, остановитесь и прочитайте ошибку, не завершайте чужие Node-процессы. Открытый start-windows.bat можно остановить Ctrl+C. Дождитесь успешного завершения установки зависимостей и сборки.
4. Запустите TubeStudio через ярлык. В браузере нажмите Ctrl+F5. Рядом с названием должна появиться v0.12.43-preview.1.
5. Если есть предупреждение о разных версиях — запишите обе версии. После завершения обновления перезапустите сервер и обновите страницу; «Проверить версии» повторяет только локальное чтение версии, не обновляет программу. Если версия сервера недоступна, совпадение не считается подтверждённым.
6. Запустите diagnose-windows.bat; при проблемах пришлите windows-check.log или точный текст ошибки. Установка ярлыка и диагностика не заменяют проверку фактического обновления и сохранённых данных.

Первая загрузка старого закешированного .41-интерфейса может ещё не показывать новую функцию; сначала обновите страницу Ctrl+F5. Совпадение номера не доказывает целостность всех файлов и не принимает Google/AI.

## Локальные автоматические проверки
```bash
npm ci
npm run typecheck
npm run test:unit
npm run build
npm run check:windows
node --test --test-concurrency=1 tests/e2e/backup-ui.test.mjs
npm run test:backup-transfer
```
Для браузерных тестов нужен Chromium, при необходимости задайте CHROME_PATH. TEST_ARTIFACTS_DIR задаёт папку PNG нового теста; по умолчанию используется системная временная папка. Все его данные синтетические, сервер на loopback, внешние браузерные запросы блокируются.

Общая регрессия без расширения в Bash:
```bash
files=()
for f in tests/e2e/*.test.mjs; do
  [[ "$f" == */extension.test.mjs ]] || files+=("$f")
done
node --test --test-concurrency=1 "${files[@]}"
```
Полный npm run test:e2e включает расширение и не равен выполненному прогону без него. Реальный npm run smoke с ключами не запускался и может расходовать деньги/квоту. Нативная Windows-приёмка новой .43 пока ожидает подтверждения владельца установки. Остальные условия приёмки калькулятора и переноса сохранены в LOCAL-CHECK-v0.12.41-preview.1.md.


## Ручная проверка переноса на Windows — ещё не выполнена

1. В исходной установке проверьте номер .42. Завершите задачи. Сделайте защищённую файловую копию DATA_DIR, PROMPTS_DIR и .env при остановленном сервере; затем запустите его для ZIP-экспорта. Не публикуйте ZIP: он может содержать активный OAuth-токен и личные данные.
2. Подготовьте **отдельную тестовую папку установки**, без общих с рабочей установкой DATA_DIR/PROMPTS_DIR. Не используйте junctions/ссылки на рабочие каталоги. Запускайте только одну из установок за раз либо задайте разные порты. В тестовой установке укажите её собственные пути и .env; не присылайте его в чат.
3. Перед импортом проверьте, что браузер открыт именно на тестовом сервере. Сохраните её текущие данные; импорт заменяет совпадающие файлы. В Настройки → Данные импортируйте ZIP и запишите число импортированных/пропущенных файлов и предупреждения.
4. Остановите тестовый сервер, запустите его снова, обновите страницу. Проверьте выбранный проект и сценарии/медиа, расчёт прибыли и сохранённую базу затрат, ветку рекламного плана, историю Coach, настройки и тексты/версии промптов. Другие используемые разделы проверьте отдельно.
5. Откройте старую историю без генерации и обновления Google. Не считайте импорт подтверждением действительности OAuth. Сохранённые подключения oauth-connections не переносятся обычным ZIP; при необходимости настройте их отдельно. .env в ZIP не входит.
6. Проверьте, что исходная рабочая установка осталась нетронутой. Не удаляйте исходные данные, пока не закончите проверку. При ошибке остановитесь и сохраните резервные копии; не повторяйте импорт поверх рабочей установки вслепую.
7. Для отчёта достаточно версии приложения/Windows, количества файлов, результата перезапуска и перечня проверенных разделов. Присылайте только очищенный текст ошибки/скриншот — не .env, oauth.json и не архив данных.

Локальный повторяемый API-тест: npm run test:backup-transfer. Результат и ограничения: BACKUP-TRANSFER-CHECK-v0.12.42-preview.1.md. Это не проверка нативных диалогов/ACL и не полная приёмка всех разделов.


## Дополнительная ручная проверка .43
На 390 px импортируйте тестовую копию в отдельной установке. При длинном имени пропущенного файла текст должен оставаться внутри карточки. Проверьте отмену подтверждения, понятную ошибку неправильного ZIP и повторный выбор того же файла; не используйте единственную рабочую копию для эксперимента. После успешного импорта перезапустите именно тестовый сервер и откройте выбранный проект/расчёт. Проверка на Linux: RELEASE-v0.12.43-preview.1.md; нативная Windows пока не подтверждена.
