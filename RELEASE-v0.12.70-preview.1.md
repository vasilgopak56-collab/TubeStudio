# 0.12.70-preview.1 — пакет B, часть 2: тариф новых операций

Промежуточный этап, **не завершение пакета B** и не гарантия общего предела списаний.

## Сделано

- В usage.json добавлен pricingV1: прежний агрегат отдельно как legacy, новые операции отдельно. ID, время UTC, провайдер, модель, задача, доступный до отправки тариф/источник/версия, объём и оценка USD. Снимок сохраняется перед генерацией в памяти и записывается после успешно полученного ответа. Смена настроек его не переоценивает. Это не подтверждённый счёт провайдера и не запрет редактирования JSON вручную.
- Учёт в фактических адаптерах текста, изображений, AnyModel TTS/проб/частей, аудио и поиска. Одинаковые ID разных провайдеров не сливают новые операции. Запись частей TTS происходит по мере успеха, а не только после всего выпуска. Удалён двойной агрегатный учёт над адаптерами.
- AnyModel: только свежий локальный каталог до отправки, без нового сетевого запроса ради тарифа. Нет коэффициентов/масштаба — неизвестная цена, не fallback-единица. Неизвестный объём также null. Поиск AnyModel — явно встроенная оценка 40 000 балансовых токенов/запрос, не тариф из кабинета. Прямой grounding-поиск не выдаётся за бесплатный.
- Полный итог новых строк остаётся неизвестным при null; известный subtotal отдельно. Панель различает текущую оценку старых строк и сохранённый тариф новых; до 50 строк, полный файл в резервной копии. Ошибки чтения больше не выглядят доказанным нулём.
- Запись счётчиков и операций вместе одним rename в очереди процесса. При ошибке записи результат генерации не теряется из-за повтора учёта и провайдер не вызывается заново. Следующая запись повторяет только файловое сохранение pending. Отдельная кнопка «Повторить запись журнала» (защищённый POST /usage/retry-accounting) позволяет сделать это локально, не запуская платную задачу и не отключая бюджет. В block с положительным лимитом флаг сбоя учёта останавливает новые поддерживаемые запросы.
- Проверяется структура нового журнала, единицы и согласованность стоимости со снимком; повреждение не перезаписывается нулём. Предел текущего файла 10 000 операций/8 МиБ. Резервная копия переносит снимки с неизменными байтами.

## Осознанные ограничения

**Автоматический режим калькулятора прибыли временно не принимает pricingV1**: он ранее переоценивал агрегат текущими ставками. Вместо тихой переоценки — объяснение и ручной режим. Старые сохранённые расчёты доступны. Подключение нового формата к проверяемому основанию прибыли остаётся обязательной задачей.

Не реализованы запрет неизвестного тарифа до отправки и отдельное согласие warn. Новые тарифные снимки не заменяют эти барьеры. Нет резервирования, межпроцессного ограничения, транзакции с внешним провайдером или fsync-гарантии. Нет полного учёта HTTP-ошибок, отмен, таймаутов, попыток retry и неизвестного исхода, хотя они могут оплачиваться. Повтор transport внутри одного запроса не получает отдельный гарантированный финансовый ID. Это не полный финансовый ledger.

Pending живёт только в памяти до следующей успешной записи. Перезапуск его теряет; pending прошлого месяца автоматически в новый не переносится. При некорректных данных или переполнении часть записи может не удерживаться; нужна сверка. Месяц UTC по-прежнему сбрасывает текущий журнал, бессрочного архива нет. Два процесса с одним DATA_DIR не поддерживаются финансовой очередью.

Legacy не восстанавливает надёжно провайдера, задачу и старую цену. Прежние ограничения orphan AM и смешанных ID в старом агрегате не исправлены выдуманным происхождением. Известность показанных строк не равна полноте всех внешних списаний. Денежная арифметика — number JavaScript, не decimal.

API: новые cost.valuation captured-tariff/mixed-estimate-and-captured, operationId/provider, recordedOperations/legacyRows/accountingWarning/pendingOperations; новые kinds tts/audio. TTS balanceTokens может быть null. GET /usage для некорректного файла теперь возвращает ошибку. .env, пользовательские промпты и расширение не менялись.
