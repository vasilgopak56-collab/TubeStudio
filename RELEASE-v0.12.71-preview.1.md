# 0.12.71-preview.1 — сохранённые тарифы в калькуляторе прибыли

Промежуточная сборка: интеграция прибыли выполнена; **пакет B ещё не завершён**.

## Сделано

- Автоматический режим прибыли принимает pricingV1. Для старых строк оценивается только pricingV1.legacy; совместимые общие счётчики с новыми операциями не включаются повторно.
- Новые операции считаются по их сохранённым тарифам/объёмам. Одинаковые ID разных провайдеров и задачи text/image/audio/tts/search не сливаются в одну сегодняшнюю ставку. Изменение настроек не переоценивает новые операции.
- Проверяемое основание costBasis:2 хранит старые строки, операции и accountingComplete. Внешний формат расчёта остаётся version:2; старые costBasis:1 и расчёты version:1 читаются прежним способом без автоматической миграции/переоценки.
- При неизвестной цене/объёме либо известной ошибке записи журнала показана только известная часть затрат. Прибыль, маржа и окупаемость остаются null. Локальный повтор записи не генерирует заново; уже сохранённый неполный расчёт сам не меняется.
- Хеш предпросмотра включает сохранённые операции и полноту. Новая операция или изменение использованной legacy-ставки/дня UTC требуют обновить расходы (409), а изменение неиспользованной текущей ставки не инвалидирует captured-only основание.
- Чтение проверяет структуру, уникальные ID, месяц и согласованность стоимости с тарифом/объёмом; сохранённый расчёт также проверяет хеш, формулы и итоги. Хеш не является подписью провайдера или доказательством полноты внешних списаний.
- UI отдельно показывает legacy-оценки и известные суммы по сохранённым тарифам. Первые 50 новых операций раскрываются до тарифа/объёма; полное основание сохранённого расчёта включено в JSON/Markdown и приватный ZIP.
- Лимит исходного usage.json при чтении для прибыли — 8 МиБ. Лимит самого снимка прибыли — 2 МиБ, проверяется ДО записи: превышение возвращает 413 без усечения основания. Можно сохранить журнал отдельно и использовать ручной режим со сверенными расходами.
- Встроенная справка и 63-главное Markdown-руководство обновлены. Промпты провайдеров и расширение не менялись.

## Границы

Автоматический расчёт — вся установка за текущий месяц UTC, не расходы выбранного проекта/канала. Legacy остаётся оценкой по ставкам на момент чтения и не восстанавливает достоверное происхождение смешанных ID. При отсутствии legacy AM-строк общая ставка legacy равна 0 как неприменимая; она не применяется к новым операциям с собственным тарифом. Денежная арифметика — number JavaScript, не decimal.

Не реализованы запрет неизвестного тарифа непосредственно перед фактической отправкой, отдельное согласие warn, резервирование и межпроцессный потолок. По-прежнему нет полного учёта всех HTTP-ошибок/transport retry/таймаутов/отмен/неизвестных исходов, durable pending после падения процесса или архива месяцев. Pending в памяти не входит в ZIP. Не повторяйте генерацию ради учёта.
