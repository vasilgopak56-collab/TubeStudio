# Сохранённые OAuth-подключения — v0.12.15

## Порядок работы
1. Моя аналитика → Обзор: настройте OAuth Client ID/secret и подключите свой канал через Google.
2. Каналы → Сохранённые подключения → **Запомнить текущее подключение**, прочитайте подтверждение. Без этой кнопки подключение не копируется в новое хранилище, включая вход через callback.
3. Для второго канала выберите другой канал в Google и отдельно запомните его. Вход сам по себе не сохраняет предыдущий активный токен.
4. Завершите все фоновые задачи, сохраните правки. У нужного канала нажмите **Проверить и активировать** и подтвердите. Программа принудительно обновит токен, запросит identity через YouTube Data API и проверит точный ID. Новый Google-вход не открывается, пока сохранённое разрешение работает.
5. После успеха страница перезагрузится на вкладку Каналы: несохранённые поля и кэш прежнего канала сбросятся, сохранённые отчёты останутся. Затем отдельно запросите нужный отчёт за период.

Один активный канал. Нет массового обновления, фоновой проверки списка или одновременных OAuth-запросов нескольких каналов. Сам список/обновление локального списка не обращаются в Google. Сохранение и активация делают token refresh и проверку канала, не вызывают AI и не создают статистический снимок. Старый Обзор может отдельно автоматически запрашивать свою статистику при загрузке страницы.

## Разрешения и ошибки
Подключение привязано к точному OAuth Client ID. Несовпадение отклоняется до сети; с другим клиентом войдите заново. Refresh-токен может истечь/быть отозван. Ошибка проверки не заменяет активное подключение и не выдаёт ответ Google с потенциальными секретами в интерфейс. Повторите вход Google и явное сохранение. Фактически полученный scope сохраняется; если refresh его не вернул, прежнее знание scope сохраняется, неизвестное не превращается в финансовый доступ. Новых разрешений эта функция не запрашивает. Дата проверки — история, не гарантия текущего доступа.

**Забыть сохранённое** удаляет только выбранную локальную копию, не активный oauth.json, снимки или разрешение Google. Для активного канала копию тоже можно забыть без отключения. Глобальная кнопка отключения Google остаётся отдельным действием: сохранённые копии не удаляются автоматически, но отзыв может затронуть другие разрешения того же проекта и сделать их неработоспособными. Не используйте «забыть» как отзыв доступа.

Проверки смены подключения и очередь записей защищают один процесс сервера; не запускайте несколько серверов с общей папкой данных. Запись сохранённого слота и активного oauth.json — два файла, не общая транзакция. При дисковом сбое после сохранения слота активный токен может остаться прежним: прочитайте ошибку, обновите список/статус, не считайте переключение успешным. Сетевой отказ до записи не меняет эти файлы.

## Хранение и резервная копия
DATA_DIR/oauth-connections/UC<22 символа>.json: до 50 файлов, до 128 КиБ на файл, строгая схема/ID, без символических ссылок. Новая папка 0700, новые атомарные JSON 0600 (на Windows защита зависит от ACL). Внутри **незашифрованные access/refresh-токены**, ID клиента и метаданные канала. Список в браузере содержит только ID/название/времена/флаги, не токены, client secret или raw scope.

**Хранилище исключено из обычного ZIP export/import**; экспорт отмечает пропуск. Активный oauth.json по-прежнему может входить в старый общий ZIP — архив остаётся приватным. При отдельной файловой копии завершите задачи, остановите сервер и храните папку только защищённо; перенос — с соответствующим OAuth Client ID и правами ОС. `.env` отдельно; не публикуйте его или токены. Восстановление копии не восстанавливает отозванное разрешение. Удаление, повреждение или неправильный файл не подменяются пустым успешным сохранением.

Снимки каналов/географии/дохода не переносятся и не удаляются при переключении. ИИ-уроки теперь закреплены за ID: старые уроки без ID или другого канала скрыты, но исходный yt-lessons.json не удалён. Чтобы получить уроки активного канала, явно запустите AI заново (возможен платный вызов). MCP, Chrome-токен и расширение доступа к хранилищу не получили. При отсутствии APP_PASSWORD HTTP-интерфейс не получает новой защиты: следуйте прежним настройкам безопасности и не открывайте локальный сервер посторонним.

## Проверки и открытые работы
Новые проверки используют искусственные токены и закрытый тестовый провайдер, без Drive-ключей. Итоговые результаты — RELEASE-v0.12.15.md. Нужна отдельная живая приёмка Google на двух доступных каналах, включая финансовые разрешения при их наличии; Windows/ярлык, установленное расширение и платные модели не подтверждены этой регрессией. Автоматические показы/CTR/результаты A/B и весь план ещё не закрыты.
