# Обслуживание TubeStudio v0.12.3

## Общая очередь
На один запущенный процесс сервера действуют общие FIFO-лимиты:
- 2 запроса текста или распознавания аудио;
- 3 задания генерации изображений (слот удерживается и во время опроса готовности);
- 1 запрос озвучки.

Лимит общий для всех страниц, фоновых задач и провайдеров: AnyModel и прямых Claude/Gemini/OpenAI. Переключение на резерв не создаёт вложенную очередь. Метаданные, каталог моделей, баланс и YouTube-поиск в эти три очереди не входят. Отдельные процессы программы не делят очередь между собой. Это очередь в памяти, не распределённый/постоянный планировщик: после перезапуска задания не возобновляются автоматически.

## Отмена
Кнопка «Остановить» прерывает ожидание слота, fetch, задержки повторов/Retry-After, опрос картинки и FFmpeg при сборке видео или изменении скорости/тона голоса. Отменённый вызов не запускает резервную модель. Отмена до получения ID задачи отправляет отмену, как только ID станет известен. Разрыв SSE сам по себе не равен отмене.

Уже принятый провайдером запрос может продолжать выполняться на его стороне и быть оплачен: отмена локального соединения не отменяет счёт провайдера. Учёт расходов в приложении — оценка, особенно при отмене/сетевых ошибках. Повторы после 429/5xx/сетевых ошибок сохранены там, где они уже были; это не гарантия отсутствия повторного списания. Для распознавания аудио автоматического повторного платного POST нет.

Успевшие сохраниться промежуточные результаты не удаляются, особенно готовые фрагменты транскрипции. Прерванный этап конвейера возвращается в ожидание, конвейер ставится на паузу. После продолжения этап может повториться — проверьте уже полученные материалы. Загрузка и начальное декодирование аудиофайла не являются фоновой задачей с кнопкой отмены; для декодирования остаётся отдельный лимит 90 секунд.

## Очистка кеша
Откройте Настройки → Обслуживание и очередь. Показаны занятые/ожидающие слоты и размер кеша.

«Очистить кеш» требует подтверждения и очищает только `DATA_DIR/cache`; также сбрасываются кеш каталога AnyModel и результаты проверки ключей в памяти. Ответы запросов, начавшихся до очистки, не заполняют очищенный файловый кеш заново. Новые запросы могут создать новые файлы сразу после очистки. Очищение не запускает проверку ключей или генерацию само по себе, но открытые страницы могут продолжать свои обычные запросы.

Не удаляются проекты, история исследований/конвейеров/проверок, OAuth-подключение, промпты, `.env`, исходные медиа, PCM и учёт квоты/расходов. Полная очистка аудио/PCM этим действием не производится. Повторный поиск/генерация может снова расходовать квоту YouTube и баланс провайдера. Очистка не восстанавливает исчерпанную квоту и не пополняет баланс. Защитные задержки недоступных моделей не сбрасываются.

API (с обычной авторизацией приложения): `GET /api/system/runtime`, `POST /api/system/cache/clear`.

## Журнал
Pino пишет JSON Lines в `DATA_DIR/logs/app.log`; DATA_DIR по умолчанию — папка `data` в корне программы. Активный файл до 10 МиБ и до 5 предыдущих `app.log.1` … `app.log.5`, старые удаляются при ротации. Записи слишком большого размера заменяются технической отметкой, а не разрывают лимит. Права файла — 0600 там, где это поддерживается; на Windows доступ определяется также ACL папки пользователя.

Записываются технические события: запуск, метод/путь HTTP без query, статус, длительность, ID/исход задачи, переход на резерв, очистка кеша. Тела запросов/ответов, тексты сценариев/промптов, аудио, ключи и OAuth-токены не журналируются. Дополнительно маскируются известные секреты, Bearer, чувствительные поля и OAuth-параметры. Не вставляйте секреты в имена файлов, маршруты и ID моделей; перед отправкой журнала посторонним просмотрите его. Ошибка записи журнала выводит одно общее предупреждение в консоль и не останавливает задания.

Журнал не входит в ZIP резервной копии. `launcher-logs/shortcut-install.log` — отдельный журнал установки ярлыка, не журнал API.

## Проверка исходников
`npm install`, `npm run typecheck`, `npm run build`, `npm test`.

Модульный запуск создаёт временные DATA_DIR/PROMPTS_DIR/ENV_FILE и не наследует реальные API-ключи. Браузерные тесты используют отдельный локальный сервер, временные данные и подмены платных вызовов. Это не замена реальному сквозному прогону с провайдерами и Windows.
