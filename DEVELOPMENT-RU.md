# TubeStudio — исходный код для редактирования

Это полный исходный проект версии v0.12.45-preview.1 с отдельным Windows-помощником остановки 1.0.0, а не только готовая сборка. Его можно открывать и менять в VS Code, Cursor, WebStorm, Antigravity и других редакторах, поддерживающих обычные папки и TypeScript/React. Специальный импорт проекта не нужен.

## Как открыть

1. Распакуйте архив в отдельную папку, например `C:\Projects\TubeStudio-source`.
2. В редакторе выберите «Открыть папку / Open Folder» и укажите папку `tubestudio`, где лежит `package.json`.
3. Установите Node.js 22 LTS или 24 LTS. Для озвучки, видео и поиска пауз нужен также FFmpeg в PATH.
4. Откройте встроенный терминал редактора в корне проекта.

## Первый запуск для разработки

В Windows используйте терминал «Командная строка / Command Prompt». Если политика PowerShell блокирует npm.ps1, не отключайте защиту: переключите терминал на cmd.

```bat
copy .env.example .env
npm ci
npm run dev
```

Команду `copy` выполняйте только при отсутствии `.env`: не перезаписывайте файл со своими ключами. В macOS/Linux вместо неё: `cp -n .env.example .env`.

Откройте http://localhost:5173 — интерфейс разработки. Изменения интерфейса обновляются автоматически, сервер следит за изменениями исходников. Остановить процессы режима разработки: Ctrl+C в том терминале, где запущен npm run dev. stop-windows.bat предназначен для собранного сервера с абсолютным путём и не должен завершать dev-процессы tsx/Vite.

Сервер API по умолчанию: http://127.0.0.1:8787. Перед запуском остановите другую копию TubeStudio, использующую этот порт. Используйте отдельную папку исходников и отдельные данные; не направляйте DATA_DIR или PROMPTS_DIR на единственную рабочую копию и не копируйте её .env без необходимости. Если меняете PORT в `.env`, измените адрес прокси `/api` и `/files` в `apps/web/vite.config.ts` на тот же порт.

Ключи можно ввести через настройки программы. В архиве нет настоящих API-ключей, OAuth-токенов, ваших проектов и загруженной озвучки. Подключение к платным моделям требует собственных ключей и баланса; правка кода сама по себе не требует запросов к ИИ.

## Где что менять

| Путь | Содержимое |
| --- | --- |
| `apps/web/src/pages/` | Экраны и формы приложения |
| `apps/web/src/components/` | Переиспользуемые элементы интерфейса |
| `apps/web/src/lib/help.ts` | Встроенная справка |
| `apps/web/src/lib/nav.tsx` | Навигация |
| `apps/server/src/index.ts` | Запуск сервера и подключение маршрутов |
| `apps/server/src/routes/` | API и обработчики инструментов |
| `apps/server/src/services/` | Логика сервисов и интеграций |
| `apps/server/src/lib/` | Общие серверные функции |
| `apps/server/prompts/` | Промпты |
| `windows/` и корневые `.bat` | Запуск, обновление, создание ярлыка Windows |
| `apps/server/test/` | Модульные тесты |
| `tests/e2e/` | Браузерные тесты |
| `scripts/build-docs.ts` | Генератор Word-документации |
| `extension/` | Исходники расширения браузера |

Технологии: TypeScript, React 18, Vite, Tailwind CSS; сервер Node.js и Hono. Зависимости и команды описаны в корневом `package.json` и `apps/*/package.json`, точные версии зафиксированы в `package-lock.json`.

## Проверка правок

```bat
npm run typecheck
npm run test:unit
npm run build
```

Браузерные тесты: `npm run test:e2e`. Для них нужен доступный Chromium/Chrome и настройки окружения из файлов `tests/e2e/`; без подготовки браузера они могут не запуститься.

## Запуск готовой сборки после правок

Остановите режим разработки (Ctrl+C), затем:

```bat
npm run build
npm start
```

Откройте http://127.0.0.1:8787 (или свой PORT). Окно терминала должно оставаться открытым. Один `npm start` не пересобирает изменённый код.

## Важные ограничения

- Это исходный веб-проект, работающий локально, а не установщик EXE и не проект Visual Studio `.sln`.
- Для редактирования не нужно запускать `update-windows.bat` или создавать ярлык.
- Установщик ярлыка v0.12.2 сохраняет журнал `launcher-logs/shortcut-install.log`, определяет перенаправленный рабочий стол и перечитывает сохранённый .lnk. Для диагностики используйте `create-desktop-shortcut.bat` от своего обычного пользователя. Проверка кода в Linux не подтверждает создание ярлыка на вашем Windows.
- Не переносите реальные ключи в исходники, не публикуйте `.env`, папки данных и журналы. При передаче проекта сначала проверьте отсутствие секретов.
- По умолчанию запускайте исходники отдельно от рабочей установки. Не копируйте рабочие данные поверх неизвестной версии без резервной копии. ZIP-импорт v0.12.2 восстанавливает текущие разделы и промпты. Для большой файловой копии остановите сервер и сохраните DATA_DIR, PROMPTS_DIR (обычно apps/server/prompts) и `.env` отдельно; см. `BACKUP-README.md`. Архив данных может содержать OAuth-токены.
- Авторы внешних библиотек сохраняют свои лицензии; этот архив не присваивает исходникам новую лицензию.


## Диагностика Windows

`npm run check:windows` — переносимая проверка файлов запуска. На Windows: `diagnose-windows.bat` для проверки Node.js и существующего ярлыка, без старта сервера и чтения ключей. Подробности: WINDOWS-CHECK-README.md. Linux-тесты не подтверждают фактический запуск .lnk.


## Последний состав архива исходников

В комплект включены web, server, MCP, промпты, тесты, package-lock.json и Windows-файлы, включая stop-windows.bat и windows/server-control.mjs. Имеющийся код расширения сохранён, но дальнейшая разработка расширения исключена по решению пользователя.

Нет node_modules, dist, настоящего .env, рабочих data, OAuth-токенов и журналов запуска. После распаковки зависимости устанавливаются через npm ci; готовая production-сборка создаётся npm run build. Архив не является EXE-установщиком или Visual Studio .sln и не восстанавливает вашу пользовательскую базу.

Состояние проверок и известные ограничения: PREVIEW-CHECKS.json. Последний полный браузерный прогон .43: 295 E2E без расширения; после Windows-дополнения — 614 модульных тестов. Нативные Windows-функции требуют отдельной проверки на целевой машине. Перед переносом своих изменений в рабочую установку остановите её и сделайте защищённую резервную копию.

## Отдельная нативная проверка остановки Windows

В проект включены test-stop-windows.bat и WINDOWS-STOP-TEST-README.md. Они не запускают полное приложение и не требуют npm-зависимостей/ключей: только синтетические временные серверы для проверки помощника остановки. На Linux отказываются до запуска. Это необязательный инструмент приёмки, не замена Ctrl+C для npm run dev и не доказательство прохождения всей Windows-приёмки. Не запускайте от администратора и не обходите защитные политики ради PASS.
