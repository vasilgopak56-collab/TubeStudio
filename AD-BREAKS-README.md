# Рекламные паузы — основание v0.12.39-preview.1

## Что изменено сейчас
- Новый план version: 2 хранит basis: algorithm `saved-gap-midpoint-greedy-v1`, все границы речевых сегментов и сохранённых пауз, первые 160 символов текста каждого сегмента. Полное аудио/полный сценарий не копируются. Метаданные источника и настройки закреплены в плане.
- Для каждой соседней пары указан результат: кандидат, нет положительного зазора, нет достаточно длинного пересечения с сохранённой паузой, нет внутренней точки после округления или точка исключена отступами начала/конца. Отсутствие сохранённых пауз не означает акустическое отсутствие тишины.
- Автовыбор показывает порядок по длине интервала и времени, выбранные точки, конфликты расстояния с ранее выбранными или уже достигнутую цель. Это объяснение прежней жадной эвристики, не новая оптимизация удержания. При достигнутой цели расстояние для оставшихся кандидатов не проверяется.
- Ручное сохранение создаёт новый снимок и сохраняет первоначальный basis/autoSelectedN; current.selectedN — отдельный текущий выбор. Несохранённые галочки не меняют эти сохранённые поля.
- SHA-256 связывает **сохранённую проекцию** источника и настройки. Это не хеш аудиофайла, подпись или доказательство подлинности/прослушивания. При чтении v2 сервер заново вычисляет кандидатов и объяснение по проекции, проверяет хеш и согласованность; живой источник не читает. Это проверка данных, не повторный акустический анализ.
- Архив v1 без basis открывается и допускает ручное ветвление как v1. Основание задним числом не восстанавливается. Страница показывает явное предупреждение.
- Раскрываемое основание на странице, JSON и Markdown; TXT остаётся списком сохранённых выбранных точек с метаданными/ограничениями, без невыбранных таймкодов. Markdown помещает основание в ограду длиннее содержащихся в тексте обратных кавычек.
- Категория MCP ad-breaks остаётся opt-in и read-only. Формат v2 читается, но новая проекция границ/basis в ответы MCP не добавлена. Уже доступные тексты кандидатов остаются доступны по прежним правилам.

Проверки v0.12.39-preview.1: типы и production-сборки web/server/MCP прошли; **583 модульных теста и 6 целевых браузерных сценариев рекламных пауз**, ошибок 0. Просмотрены четыре экрана пауз: раскрытое основание v2 и архив v1 на 1440/390 px, переполнения страницы нет. Windows — только файловая проверка на Linux. **Полный набор E2E, браузерная/визуальная приёмка калькулятора и нативная Windows-приёмка не выполнены.**

**Вся сборка остаётся preview** из-за незавершённой браузерной/визуальной приёмки калькулятора. Сохранённые планы могут содержать приватный текст всех сегментов (короткие проекции), поэтому не публикуйте выгрузки. ZIP-перенос включает их как раньше. Автоматической вставки рекламы, распознавания смысловых границ и проверки монетизации нет.

## Базовое поведение v0.12.8 (сохраняется, с дополнениями выше)

# Рекламные паузы — v0.12.8

## Что добавлено
Создание контента → Рекламные паузы, адрес /ad-breaks. Локальный план точек для ручного монтажа по сохранённым сегментам аудио. Не вставляет рекламу, не изменяет аудиофайл или YouTube, не проверяет монетизацию. Планирование не вызывает модели, FFmpeg или внешние API, ключи не нужны.

## Как использовать
1. В «Из озвучки» загрузите аудио, найдите паузы и проверьте/сохраните границы речевых сегментов. Нужны минимум два сегмента. Распознавать речь и генерировать промпты не обязательно. Подготовка аудио по-прежнему требует FFmpeg.
2. Перейдите по ссылке «Рекламные паузы →» в карточке аудио либо откройте новый раздел в меню. Ссылка не переводит при несохранённых правках или выполняющемся задании. Выберите файл из последних 30 корректных сохранённых источников; при отсутствии старого файла откройте/сохраните его в «Из озвучки» и обновите список.
3. Укажите название, минимальную длину паузы, отступы от начала и конца, минимальное расстояние между точками и цель 1–20 точек. Все значения времени — секунды. По умолчанию: 0,5 / 60 / 30 / 120 секунд и 3 точки. Это эвристические настройки пользователя, НЕ требования YouTube и НЕ обещание заработка.
4. «Подобрать и сохранить план» создаёт снимок с автовыбором. Если исходная версия изменилась, сервер возвращает конфликт: обновите список и выберите файл заново. Исходник и старый план не перезаписываются.
5. Прослушайте оригинальную озвучку в «Из озвучки». Проверьте завершённость мысли. Отметьте подходящие точки и нажмите «Сохранить выбор». Допускаются до 20 точек с заданным интервалом, включая пустой выбор; нельзя подставить произвольный таймкод внутри речи. При ошибке текущий выбор и предыдущий снимок сохраняются.
6. Копирование таймкодов, TXT, Markdown и JSON доступны для сохранённого результата. При несохранённом выборе экспорт блокируется; «Отменить выбор» возвращает сохранённые отметки. Создание нового плана/открытие истории/переход к озвучке спрашивает подтверждение потери несохранённого выбора. Переходы через общее меню не защищены этим подтверждением: сохраняйте выбор до навигации.

## Алгоритм и границы достоверности
- Для каждой пары соседних речевых сегментов берётся положительный зазор между концом первого и началом следующего.
- Из сохранённых пауз выбирается самый длинный подходящий интервал пересечения с этим зазором. Кандидат — его середина, округлённая до миллисекунд и строго внутри интервала/зазора. Нулевые зазоры и интервалы короче минимума пропускаются.
- Кандидат должен проходить отступы начала/конца. Программа не сдвигает его в речь и не создаёт равномерные искусственные точки при нехватке пауз.
- Автовыбор: по убыванию длины паузы (при равенстве — раньше по времени), добавление до целевого количества, только если расстояние до всех выбранных не меньше заданного. Вывод по хронологии. Это детерминированная жадная эвристика, не математически оптимальное размещение: иногда другой ручной набор даст больше точек.
- Ручной выбор выполняется среди тех же кандидатов, с проверкой расстояния и лимита 20. Цель — ориентир автовыбора, а не жёсткий предел ручного выбора.
- Первоначальный детектор использует локальный RMS. После ручного редактирования сегментов сохранённые паузы пересчитываются из их границ и не обязательно соответствуют акустической тишине. Планировщик не повторяет анализ звука, не проверяет семантику/удержание. Разрешение записи миллисекунд не означает такую же акустическую точность.
- Таймкоды — от начала оригинальной озвучки. После монтажа со сдвигами они могут не совпадать с финальным видео. Условия и доступность рекламы проверяйте отдельно в YouTube Studio; автоматического переноса туда нет.

## История, экспорт и приватность
DATA_DIR/ad-break-runs/<UUID>.json: источник (ID/имя/ревизия/время/длительность), настройки, все кандидаты с короткими отрывками текста до/после, выбранные номера, предупреждения. Аудио, полный сценарий, ключи и OAuth в план не копируются. Снимки могут содержать приватный текст: не публикуйте архивы/выгрузки без проверки.

Каждый расчёт и каждое сохранение выбора — отдельный неизменяемый снимок. rootId и parentId сохраняют ветвление выбора. Смена формы или исходной озвучки не пересчитывает старый результат. История показывает последние 50 корректных снимков без удаления старых файлов. Снимок можно открыть и после отсутствия исходника, но прослушивание тогда невозможно.

TXT — заголовок, источник, настройки, выбранные таймкоды HH:MM:SS.mmm и ограничения. Markdown дополнительно содержит короткие отрывки соседних сегментов. JSON содержит все кандидаты и selectedN; новые v2 также включают basis. Markdown v2 дополнительно содержит basis в JSON-блоке; наличие кандидата в JSON не означает, что он выбран. Пустой список корректен. Отдельного импорта JSON нет; общий ZIP-перенос включает ad-break-runs. Проверка переноса каталогов автоматизирована.

## Обновление и редактирование исходников
Завершите задания, остановите сервер и сделайте резервную копию текущей папки, DATA_DIR, .env и своих промптов. Скопируйте содержимое tubestudio из архива исходников в существующую папку с заменой файлов, НЕ создавая вложенную tubestudio. Не удаляйте .env, data или apps/server/data. Запустите update-windows.bat, дождитесь успеха и обновите страницу Ctrl+F5. Требуется установленный Node.js.

Исходники доступны для правок в IDE. Проверки: npm run typecheck, npm run build, npm run test:unit, npm run test:e2e. Не используйте npm run smoke с приватными ключами без отдельного согласования. Основные новые файлы: services/adBreaks.ts, routes/adBreaks.ts, pages/AdBreaks.tsx, features/ad-breaks/types.ts. Исторические PDF/DOCX v0.11 не пересобраны; Windows-ярлык и реальные провайдеры требуют отдельной приёмки.
