# SEO-аудит оформления — v0.12.34

**Создание контента → SEO-аудит** (`/seo-audit`). Это редакторский контрольный список и отдельная сохранённая страница ответа YouTube Data API, а не измерение SEO-эффективности. Старые разделы «SEO» (генерация) и «Перед публикацией» (AI-рецензия) не заменены.

## Работа
1. Введите заголовок, описание, теги через запятую/новую строку и необязательную целевую фразу. Нажмите **Проверить и сохранить локально**. Ключ и AI для этого не нужны; введённый текст эта операция не отправляет внешним сервисам.
2. Прочитайте шесть наблюдений и ручных проверок. В «Сохранённом тексте и методике» виден закреплённый ввод. Текущая форма независима от него: изменённый текст нужно проверить новой кнопкой, иначе поиск/экспорт относятся к прежнему снимку.
3. При необходимости введите отдельный поисковый запрос, язык релевантности, регион из двух латинских букв (либо оставьте пустым) и ссылку/ID опубликованного видео для локального сопоставления. Целевая фраза подставляется как черновик запроса, но сама поиск не запускает. Если её нет, запрос нужно ввести вручную.
4. Сначала нажмите **Предпросмотр поискового запроса**: это локальная операция без ключа/квоты. Проверьте публичные параметры, источник и локальный ID сопоставления. После изменения параметров/источника обновите предпросмотр. Затем **Искать для этой проверки (100 ед.)** запрашивает ровно одну свежую страницу `search.list`, до 50 видео, `type=video`, `part=snippet`, `order=relevance`, `safeSearch=moderate`. Нет загрузки следующей страницы, дополнительных метаданных, кеширования или сортировки ответа. Повторная кнопка — новый запрос и новый снимок.
5. **Проверка JSON** экспортирует именно текущий сохранённый результат. История открывает последние 50 локальных проверок без повторения поиска. Общий ZIP данных переносит папку `seo-audit-runs`.

## Что означает локальная методика v1
- Длины считаются в единицах UTF-16 (например, многие emoji занимают две), а не в символах-графемах или байтах.
- Контрольные пороги заголовка/описания/строки тегов — 100/5000/500. Это локальные ориентиры, **не точная проверка лимитов Studio и не балл SEO**. Строка тегов соединяется запятыми; реальный учёт Studio может учитывать кавычки/пробелы иначе. Нет минимально обязательного количества тегов и утверждения, что больше тегов улучшает продвижение.
- Целевая фраза сопоставляется как нормализованная подстрока: NFKC, нижний регистр, ё → е. Без морфологии, семантики или замера спроса. Первые 200 знаков описания — область этого списка, не обещание фактического отображения на YouTube. Неуказанная фраза не считается совпадением.
- Дубли тегов определяются той же нормализацией, а не приблизительной похожестью.
- Малый словарь для ручной сверки: `100%`, `без риска`, `гарантирован`, `мгновенно`, `guaranteed`, `risk-free`, `miracle cure`. Проверяются подстроки в заголовке, описании и тегах. Это **не запрещённые слова YouTube**, не проверка всех языков, монетизации или допуска публикации. Контекст может полностью менять смысл; отсутствие совпадений не означает безопасности.
- Факты, обещания, права, ссылки, качество и соответствие ролику проверяет человек. AI-рецензия здесь не вызывается. Программа не редактирует/публикует видео и не подтверждает факты.

Форма: заголовок 1–300, описание до 10 000, до 60 непустых тегов по 100, фраза до 120 единиц UTF-16. Эти пределы позволяют разобрать и чрезмерный ввод, **не являются разрешёнными пределами YouTube**. HTTP-тело ограничено 64 КиБ. Запрос поиска — 2–200; необязательное видео — валидный 11-символьный ID либо поддержанная HTTPS-ссылка YouTube. Параметры проверяются до старта задания.

## Что означает поиск
YouTube получает введённый **поисковый запрос**, язык, необязательный регион, фиксированные параметры метода и API-ключ. Заголовок/описание/теги автоматически к запросу не добавляются, ID для сопоставления используется локально. Если вручную вставить частный текст в запрос, он уйдёт Google: секреты не вставляйте.

Снимок хранит фактический порядок возвращённых строк, запрос, параметры, время получения, ID сопоставления и признак следующей страницы. Число «строка 2» — только строка **этой страницы ответа API**, не реальная позиция видео у зрителей, не результат поиска на сайте, не персонализированная выдача и не рейтинг. Не найдено среди N строк ≠ отсутствует во всём YouTube. Без ID/совпадения позиция `null`, не 0. Пустая страница остаётся пустой; отсутствие `nextPageToken` не гарантирует полный охват. Другие страницы не загружаются. Нет измерения частотности, конкуренции, поискового трафика, CTR, роста или причин успеха.

Базовый расход одного поиска — **100 единиц YouTube**, не токены AI. Общие сетевые повторы и резервные ключи могут увеличить расход. Уже отправленный запрос отменой не возвращается. Чтение истории/JSON/локальный аудит не повторяют этот поиск. Общая диагностика приложения отдельно может проверять ключи, включая минимальный текстовый запрос к настроенному провайдеру; настроенный трекер также работает независимо. Не считайте открытие приложения гарантированно бессетевым.

## Хранение и ошибки
- Локальная проверка и успешный поиск создают разные UUID-файлы; поиск ссылается на родителя и сохраняет тот же исходный текст. Изменённая форма или запрос не переписывают старый файл и его JSON.
- Ошибка/невалидный ответ/отмена до сохранения не создают новый результат и не заменяют прежний. Повтор по кнопке — новая операция. После успешного сохранения отмена не является удалением уже готового результата.
- Запись через временный файл; файлы 0600, папка 0700 там, где ОС поддерживает эти режимы. Это **не шифрование** и не гарантия Windows ACL.
- Схемы v1/v2 строгие, снимок ≤256 КиБ; новые v2 включают закреплённый request, старые v1 читаются без перезаписи/выдуманного запроса (в отчёте request:null). Несогласованный запрос/хеш v2 отклоняется; повреждённые/неподдержанные/символические ссылки пропускаются с числом пропусков. История показывает последние 50, но старые файлы автоматически не удаляются. При >5000 файлов каталога чтение истории останавливается с сообщением: архивировать часть нужно при остановленном сервере.
- В файле — исходный ввод и ответ поиска, не готовые вычисленные оценки. JSON интерфейса/GET дополнительно содержит детерминированные `local` и `searchPosition`, заново вычисленные по методике v1. Нельзя подменить их полями в сыром файле: дополнительные поля приводят к отклонению. Это проверка структуры, **не криптографическая подлинность** исходных данных.
- JSON и ZIP содержат введённый текст/запросы; храните приватно. Обычный ZIP данных приложения может включать другие приватные данные и прежний активный OAuth-токен — см. BACKUP-README.md. Исходный ZIP релиза пользовательских данных не содержит.
- Новые API наследуют пароль приложения; токен Chrome к ним не допущен. MCP и OAuth-права не расширены.
