# SEO-аудит: предпросмотр поиска и снимки v2 — v0.12.34

Продолжение пункта 9. Шесть локальных редакторских наблюдений и методика v1 остаются прежними. Нет SEO-балла, прогноза CTR/роста, проверки всех политик, реальных поисковых позиций или AI-вызова.

## Порядок действий

1. Заполнить текст и нажать **Проверить и сохранить локально**. Эта операция сохраняет текст на локальном сервере, без YouTube/AI. Сохранённый результат независим от несохранённого ввода.
2. В поисковой форме задать запрос, язык релевантности, необязательный регион (две латинские буквы), необязательный опубликованный ID/ссылку.
3. Нажать **Предпросмотр поискового запроса**. Только чтение локальной проверки, без Google, ключа и квоты. Проверить точные публичные параметры в блоке под кнопкой.
4. Нажать **Искать для этой проверки (100 ед.)**. Без актуального предпросмотра кнопка недоступна, сервер также проверяет хеш до внешнего запроса. Изменение запроса/языка/региона/ID или сохранённого исходного текста требует нового предпросмотра. После успешного поиска появляется новый снимок-родитель; следующий поиск нужно предварительно просмотреть заново.
5. Раскрыть **Сохранённый запрос этой выборки** либо скачать **Проверка JSON**. Это запрос сохранённого результата, а не текущей изменённой формы. История и ZIP его переносят без повторения поиска.

## Что показывается и отправляется

Публичный запрос: GET `https://www.googleapis.com/youtube/v3/search`, part=snippet, type=video, q, order=relevance, maxResults=50, relevanceLanguage, safeSearch=moderate; regionCode присутствует только при указанном регионе. Транспортное URL-кодирование выполняет общий клиент. API-ключ добавляется сервером и не показывается/не сохраняется в request. Выбор ключа/повторы задаются общим механизмом и не фиксируются этим снимком.

ID сопоставления используется **только локально**, не добавляется к search.list. Заголовок/описание/теги не добавляются в поисковый запрос; в предпросмотре к ним привязан локальный хеш. Если самостоятельно вставить приватный текст в поле запроса, он уйдёт Google: секреты не вводить.

Одна свежая страница до 50 видео, без следующей страницы, дополнительных метаданных, кеша, сортировки/дедупликации ответов. Повторные ID или неверная структура — ошибка, не успешная пустая страница. Пустой корректный ответ сохраняется как пустой. Базовый расход — 100 единиц, повторы/смена ключа могут увеличить его. Общая диагностика/трекер приложения работают независимо. Отмена уже отправленного запроса квоту не возвращает.

Номер совпавшей строки относится только к этой странице ответа API, не к выдаче сайта у зрителя. Нет совпадения — null, не 0 и не доказательство отсутствия ролика в поиске. Флаги следующей страницы не означают полный охват.

## Привязка и хранение

- Предпросмотр содержит ID/дату родителя, SHA-256 нормализованного сохранённого input, локальный targetId и публичные параметры. Хеш детерминированно связывает эти поля. Новые поисковые снимки v2 сохраняют этот объект как request; локальные снимки v2 — request:null.
- Сервер заново читает/проверяет источник перед поиском и отклоняет устаревший хеш. Поиск выполняется из проверенных параметров; копия input и показанный request закрепляются вместе с ответом одной страницы.
- На чтении v2 проверяются схема, уникальность ID строк, согласованность request/родителя/input/targetId/параметров и хеша. Это **не подпись и не криптографическое доказательство подлинности**: владелец файлов может пересчитать хеш.
- Сырые архивы v1 читаются без перезаписи, миграции или выдумывания точного предпросмотра. В отчёте request:null и явная подпись архива. Сохранённые query/параметры v1 по-прежнему видны. Методика локального списка не поменялась.
- Общие ограничения прежние: снимок до 256 КиБ, максимум 5000 записей каталога перед остановкой чтения истории, показываются последние 50. Символические ссылки/повреждённые/несогласованные записи пропускаются с числом пропусков. После открытия файла повторно проверяются тип и размер, чтение ограничено. Запись атомарная, режим 0600 там, где поддержан, не шифрование.
- Папка seo-audit-runs остаётся в общем ZIP. Отчёт JSON не импортируется отдельной кнопкой. Новая версия читает v1/v2; старые версии могут не понимать v2. Проверять восстановление в отдельной установке. Тексты/запросы/общий ZIP приватны.

## Ошибки и уход со страницы

Поисковое задание отменяется прежним механизмом; ошибка/отмена до сохранения не заменяет видимый результат или предыдущие файлы. После успешного сохранения отмена не удаляет готовый снимок.

HTTP-запросы локального сохранения и предпросмотра прерываются при уходе. Их поздний ответ не меняет выбранный маршрут/результат. Это **не гарантия отката уже завершённого сервером локального сохранения**: такой снимок может остаться в истории, даже если ответ не показан. Предпросмотр не создаёт файлов. Несохранённый ввод не восстанавливается автоматически.

Новых OAuth/MCP/Chrome-прав, AI-запросов, публикации/редактирования роликов нет. Реальный Google и Windows не прошли приёмку; исторические PDF/DOCX не пересобраны; весь план не закрыт.

## HTTP-контракт v0.12.34

- POST `/api/seo-audit/preview`: auditId, query, video, language, region. Возвращает локальный предпросмотр.
- POST `/api/seo-audit/search`: те же поля и **обязательный previewHash**. Без него — 400 до старта задания. Устаревший хеш — ошибка VALIDATION в потоке задания до вызова Google. Это изменение прежнего контракта: старые клиенты должны добавить явный шаг предпросмотра.
- Остальные маршруты/пароль приложения прежние, Chrome-токен к ним не допущен. Прямой произвольный request от клиента сервер не принимает.
